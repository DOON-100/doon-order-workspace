# Mastra P1：合成订单只读 API 与员工建议工作台

本目录延续 `codex/mastra-local-validation` 的隔离实验。原 P0 实验保留在 [`examples/mastra-local`](../../examples/mastra-local/README.md)。最新模型复测、员工网关及云容量状态见 [LOGIN-LIVE-ACCEPTANCE.md](./LOGIN-LIVE-ACCEPTANCE.md)；此前主线登录与权限适配见 [PROJECT-AUTH-ACCEPTANCE.md](./PROJECT-AUTH-ACCEPTANCE.md)，独立合成认证下的真实 DeepSeek 结果见 [AUTH-MODEL-ACCEPTANCE.md](./AUTH-MODEL-ACCEPTANCE.md)，早期记录保留在 [ACCEPTANCE.md](./ACCEPTANCE.md)。

预览订单、客户和员工来自 `fixtures.mjs`；`project-fixtures.mjs` 额外提供多角色、团队和三类任务权限测试，全部为合成数据。默认预览使用脚本模拟模型，显式真实联调使用 DeepSeek V4 Pro。两种入口均已接入主线认证适配器，共享受信会话、工具与建议事务链路；新认证后的真实模型复测已通过，两名员工各生成 2 条建议，累计保守费用 ¥0.283556。仅新增独立建议记录，不创建正式任务或修改订单。页面不提供批准、保存、派发或业务写回。

## 运行

从本目录执行，Node 至少 22.13，本轮验证版本为 24.19.0：

```powershell
npm ci --no-audit --no-fund
npm test
npm run preview -- --synthetic
```

按终端 `PREVIEW_READY` 的 `url` 打开页面。服务只监听 `127.0.0.1` 的系统分配端口，不使用 8787。在同条输出的 `credentialsFile` 本机私有文件中取得本轮随机合成账号和密码，登录后各看到 4 条授权订单、2 条跟进建议。文件不是 HTTP 资源，凭据不在网页、响应或终端摘要中公开；不要上传或提交此文件。

每次预览启动新建独立认证库并重新分配凭据，旧凭据及旧会话不能用于新实例。认证复用主线的 12 小时绝对期限和 2 小时空闲期限；接口返回二者较早的到期时间。退出、401/403 或到期时页面立即清空已读内容，取消旧请求，防止晚到响应回填。原生会话在同一合成认证库中可跨认证 worker 重启恢复，已另行验证。正常退出会清理认证库；预览凭据文件可随建议沙箱删除，系统临时目录不适合长期保管秘密。

`Ctrl+C` 结束本次预览。预览创建的合成建议库保留在系统临时目录，方便重新启动验证：

```powershell
npm run preview -- --synthetic --resume "<上次 PREVIEW_READY 的 directory>"
```

`--resume` 仅接受系统临时目录下带有实验标识的 `doon-mastra-p1-*` 目录，不接受任意数据库路径或链接文件。每次启动对两个合成员工重跑模拟检查，通过建议内容幂等补齐部分结果；已有记录与原运行 ID 保持不变。`--prepare-only` 完成准备后退出，不落凭据文件，供跨进程测试使用。

真实模型模式在相邻 `mastra-p2` 目录执行（先按其 README 安装独立依赖、配置被忽略的 `.env.local`）：

```powershell
npm run live:p1 -- --budget-ledger "<已有 P2 临时目录>"
```

此入口要求已有预算账本，保留此前费用；没有新建／清零账本选项。最多增加 8 个请求，预检不足则不开始；失败仍记录已有收费或未知 usage 的预留。完成后用结果中的 `sandbox` 运行上述 `preview --resume` 即可查看真实模型生成的建议；预览模拟重算不会覆盖已有内容或运行 ID。网页本身不会触发收费调用。

测试自动创建并清理自己的临时目录。预览目录可能被系统清理，不作为正式持久存储。安装只使用本目录的依赖与 lockfile，不需要在业务根目录执行安装、构建、部署或迁移。

## 数据与权限边界

可选员工网关协议预览：`node preview.mjs --synthetic --gateway-auth`；只验证初始化并立即关闭可追加 `--prepare-only`。`gateway-identity.mjs` 为此新建独立网关与 SQL 库，先通过原生 HTTP 路由完成初始改密，再把 P1 的登录／会话／退出交给该网关，每次使用都核对原生会话和只读身份上下文。它不接受自定义生产 URL、数据库或端口。`--resume` 仅恢复建议记录，不恢复该桥接器的会话。此模式仍是本机合成实验，代理头由实验客户端模拟，尚未验证真实 TLS 或浏览器对 Secure Cookie 的执行。

- `policy.mjs` 在内存中编译当前分支的 `lib/domain.ts` 并调用真实 `canRead`。编译入口只允许该纯规则文件，禁止新增依赖，不加载业务 store、运行时、数据库或附件目录。
- `project-auth.mjs` 将当前分支未修改的 `standalone/auth.mjs`、`runtime.mjs` 原文复制并核对 SHA-256，在严格限定的新临时目录中启动独立认证子进程。该进程只收到白名单环境，`DOON_DATA_DIR` 固定到合成库，不加载主 server 或业务库。复用真实建账号、首次改密、scrypt、会话、注销、撤销和登录审计。
- 账号绑定来自服务端 `session.member.id`，不使用客户端身份，也不把 `publicSession.identity.id`（账号 userId）误当成员 ID。仅合成成员／客户快照进入认证库，每次登录及解析会话均同步当前授权源，返回后再检查源是否变化；账号和密码哈希不离开子进程。停用和供应商被拒绝，内部角色可验证只读权限；建议生成仍限定 A/B 且当前角色为 sales。
- `auth.mjs` 保留为原独立内存认证的单元测试夹具，不再作为预览或真实模型入口的默认认证。原 15 分钟期限及重启失效断言只属于该夹具。
- `project-policy-loader.mjs` 在内存编译 17 个明确允许的主线权限模块，保留源码哈希。业务 store 的写入方法及 workbooks 依赖替换为抛错边界，不加载生产数据库、身份提供器或文件存储。`project-policy.mjs` 提供客户、团队和三类任务的最小只读 DTO。
- 业务 API 不接受调用者指定 `memberId` 或 `actorId`。每次请求、工具调用及最终提交重验会话和当前权限；凭据、Cookie 不传给模型。
- `POST /api/demo-session` 已关闭（404），仅 `POST /api/session` 可验证凭据建立会话。认证算法与 SQL 会话已适配主线源码，**尚未连接真实员工账号或生产登录入口**；不能直接公开部署或替换为真实数据。
- 订单 DTO 明确列出允许字段，排除邮箱、附件键、私有备注等；分页数量为 1–50，游标绑定身份、数量和可见来源指纹。权限或来源变化使旧游标失效。
- 建议保存来源 ID、版本、指纹及运行标识。来源变化时展示“来源已更新”，清空旧理由和动作；撤销来源访问后不再返回建议。
- 建议库是新建的独立 SQLite，HTTP 查询连接以只读模式打开。只有实验启动阶段的 Agent 可向该合成库新增建议。数据库、缓存、会话、日志都不提交 Git。
- 预览不加载 `.env`，不读取模型密钥；检测到列出的业务运行配置时会拒绝启动。HTTP 工具只接受本机非 8787 地址，拒绝重定向；静态资源没有 CDN。

页面中的时间与日期比较固定于合成场景 `2026-10-15 09:00 Asia/Shanghai`，不是实时订单时钟。`syn-run-<员工>-20261015` 是此固定场景的运行标识，不代表生产唯一执行 ID。归档订单可作为只读来源查询，但不会生成跟进建议。对已过去交期只提示核对履约情况，不判定订单实际逾期。

## 接口与链路

| 接口 | 用途 |
| --- | --- |
| `POST /api/session` | 仅接受 username/password，验证后建立受限合成会话 |
| `POST /api/logout` | 注销会话；不接受身份或额外字段 |
| `GET /api/me` | 当前服务端身份及会话到期时间 |
| `GET /api/orders?limit=20&cursor=...` | 授权订单白名单字段与分页 |
| `GET /api/orders/:id` | 授权来源详情，越权与不存在均为 404 |
| `GET /api/suggestions` | 当前员工可见建议，重新检查来源权限与版本 |
| `GET /api/customers?teamId=...&limit=20`、`GET /api/customers/:id` | 主线客户授权后的最小 DTO；详情权限独立于团队过滤 |
| `GET /api/teams` | 已授权团队，客户 ID 再与 CRM 可读范围取交集 |
| `GET /api/tasks?teamId=...&limit=20`、`GET /api/tasks/:id` | 三类任务各自授权；精确指派不自动授予关联客户／项目权限 |
| `GET /health` | 合成服务标识与状态 |

业务 POST/PUT/PATCH/DELETE 返回 405。主项目 `/api/*` 和 8787 路由没有注册这些实验接口。

客户／任务列表限制 1–50 条，并返回授权总数 `total`；当前无翻页游标，不能据第一页认定已完整读取全部记录。`teamId=__ungrouped` 表示未归组；团队只筛选已授权数据。任务能力字段用于核对主线规则，不代表实验开放对应写接口。仅因精确指派可读协作任务的人，DTO 隐去客户、项目和团队 ID，也不返回描述、结果、历史或附件键。订单全读与 CRM 可读分别校验。

生成链路为：合成凭据登录 → 服务端会话 → Mastra Agent（mock 或 DeepSeek）→ schema 工具 → 本机只读 API → 当前项目 `canRead` → 授权 DTO → 模型选择规则与来源 → 应用重验 → 单员工建议批次事务 → 员工只读页面。

`mock-model.mjs` 支持免费离线回归；真实模型选择来源／版本／规则，`rules.mjs` 校验依据并生成固定文案，模型自由文本不保存到员工建议。工具先暂存提案，任何错误、会话失效、版本或内容指纹变化使该员工整轮不提交；全部通过后事务写入，重复批次不新增，后项冲突回滚前项。两名员工各自一个事务，不能称跨员工整体原子提交。工具限制单页 50 条，有后续游标则中止，不生成不完整建议。

## 验证与下一阶段

2026-10-16 更新：主线认证、订单／客户／团队／三类任务权限矩阵、真实认证 HTTP 和异步会话提交检查见 [前轮报告](./PROJECT-AUTH-ACCEPTANCE.md)。新主线认证适配后的 DeepSeek 再次实测通过；本轮证据、员工网关验证及仍未完成的云验收见 [本轮报告](./LOGIN-LIVE-ACCEPTANCE.md)。历史记录保留，各轮分别计数。

`tests/policy.test.mjs` 检查权限、DTO、分页和数据不变；`tests/http.test.mjs` 检查真实 HTTP/Agent、来源失效、拒绝写入、完整及部分建议恢复；`tests/sdk.test.mjs` 额外检查 generate/stream、无记忆新上下文、工具审批和 libSQL 跨进程恢复。原 11 项集成与 5 项源码检查仍用原实验命令运行，不能用本目录测试数替代。

后续按以下门槛逐步推进；均未计入本轮通过项：

1. **真实模型质量与异常**：扩大合成场景，覆盖复杂规则、恶意来源文本、429、超时和中断；当前仅验证小样本有约束的规则建议，不能认定通用模型判断或抗提示注入能力。
2. **正式身份与权限接入**：本轮已复用主线认证及资源授权函数，用合成账号验证矩阵；仍需决定正式登录网关如何签发 Agent 专用权限、撤销与审计，以及真实源的一致性读取。当前不是完整生产路由或 SSO 认证，也不能把单应用客户隔离称作跨租户隔离。
3. **云服务器试点**：先只读核实 Ubuntu/Node 版本、现有进程、内存、磁盘、数据库与服务基线，再决定同机运行。建议独立用户、独立状态目录、单 worker、并发 1、队列与资源上限；2 vCPU/4 GiB 共享实例的可用容量必须实测，交换空间不作为运行内存容量。临时实验不替代 systemd、反向代理或故障监控方案。
4. **持久化与恢复**：以独立测试库验证最终存储方案；若使用 PostgreSQL，验证迁移、事务、权限、备份还原及进程异常退出恢复。SQLite/libSQL 成功不等于 PostgreSQL 已通过，也不要求本轮在小实例上新增数据库服务。
5. **业务写入与调度**：另行实现可信审批人、动作内容绑定、来源版本校验、事务幂等账本和不可变审计，再验证真实计时触发、重复触发、宕机补跑、企业微信回执。必须在允许业务写入之前完成这些验收。

云试点当前口径与 [v0.4 设计第 18 节](../../docs/agent-system-design.md#18-阿里云部署与容量)及[容量记录](./CLOUD-CAPACITY-ACCEPTANCE.md)一致：代表性窗口可用内存不低于 1 GiB 且不低于可见内存的 25%，无新增 OOM、持续换入换出或内存压力；另以可比负载下 P95 延迟退化不超过 10%、无新增 5xx 作为待验收的部署影响目标。以上均非实测容量结论。正式服务与 8787 不作实验目标；隔离条件不足时使用独立实例，不能凭本地测试通过批准上线。此段仅统一当前说明，历史验收报告保持当时记录。
