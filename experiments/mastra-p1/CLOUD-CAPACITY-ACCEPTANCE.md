## 采样范围与使用

脚本只读取固定的 OS 元数据和内核指标：`uname`、在线 CPU 数、`free`、根目录及 `/tmp` 所在文件系统的 `df`、`/proc/pressure/{cpu,memory,io}`、`/proc/vmstat` 的四个计数器、10 秒 `vmstat`，以及脱敏的监听端口摘要。脚本不安装工具、不申请 sudo、不修改系统或服务、不写采样文件、不连接任何端口，不读取业务目录、数据库、附件、账号、`.env`、命令行参数、进程环境或应用日志。它不会启动或调用 8787 正式服务。

默认不显示 hostname、IP、进程命令行或环境变量，也不枚举服务。需要服务占用时，只接受显式 `--service NAME.service` 白名单，最多 8 项；允许 ASCII 字母、数字、点、下划线、连字符和 `@`，禁止路径、通配符、空白及 shell 语法，拒绝重复项。名称必须先由可信运维资料确认，不能猜测运行服务。参数不会扩大业务访问权限。

在已确认实例的可信终端中运行已审查的脚本，或通过现有 Workbench `exec` 将同一脚本送入标准输入。以下只是命令说明，本轮没有运行远程命令：

```bash
bash cloud-capacity-probe.sh
# 确认实际服务名后才显式添加；此处为示例名。
bash cloud-capacity-probe.sh --service example-app.service --service nginx.service
```

单次 `vmstat -w 1 11` 包含首个“自开机以来平均值”和之后 10 个一秒区间；首行不能用于计算该窗口的负载。命令总耗时通常略大于 10 秒。采样本身有少量开销，它是被动观察，不是零开销或负载生成器。

输出是带 `BEGIN/END`、`STATUS` 和 `RESULT` 的固定标记文本。退出码 `0` 只表示本次命令执行完成；`2` 表示有指标不可用；`64` 表示参数无效；`69` 表示不是 Linux。缺失工具、无权限、空值、`[not set]` 或 `LoadState=not-found` 都不能当作零占用。脚本不会为补齐指标安装工具或改变服务的 accounting 设置。systemd 只读 `Id/LoadState/ActiveState/SubState/MainPID/NRestarts/TasksCurrent/MemoryCurrent/MemoryPeak/MemorySwapCurrent/CPUUsageNSec/MemoryHigh/MemoryMax/MemorySwapMax`，不读取 `ExecStart`、`Environment`、日志或完整 unit 配置。

服务 CPU 是累计纳秒，需用两个观察点的差值除以实际时间间隔；以整机 2 vCPU 容量为分母时再除以 2。`MemoryPeak` 是服务统计周期内峰值，不能直接等同本次窗口峰值。PSI 的 `total` 是累计值，应按前后差值判读；平均值、swap 已用量和 OOM 累计次数必须结合时间窗口，不能把过去的事件当作本次发生。

## 形成可评估的基线

至少保留正常业务、确认的业务高峰，以及备份等已知资源密集时段的被动样本。建议每个代表性窗口累计观察 30–60 分钟，分批运行短采样并标明 UTC 时间；单次 10 秒样本只能排查明显不足，不能覆盖间歇峰值。不要为取样而主动触发备份、接口请求或业务操作。没有代表性高峰数据时，结果保持“证据不足”。

可记录的证据为：实例规格的非敏感确认、采样时段和业务阶段、CPU 数、`MemAvailable` 最小值、swap 变化、`vmstat` 的运行队列/CPU idle/iowait/steal、PSI 前后变化、OOM 增量、磁盘与 inode 余量、白名单服务占用/重启次数、8787 监听状态是否变化，以及缺失指标。不得附带业务响应、账号、IP、密码或数据文件。不要只看 `free` 的 `free` 列；Linux 页缓存可回收，决策应参考 `available`。

以下是**本实验提出的保守初筛建议，不是阿里云、Mastra 或操作系统的官方保证，也不是性能承诺**。满足它们只允许讨论下一步隔离测试，不能直接宣布生产容量通过：

| 观察项 | 建议初筛门槛 |
| --- | --- |
| 内存 | 代表性窗口 `MemAvailable` 不低于 1 GiB，且不低于可见内存的 25%；没有 OOM 增量、持续 swap-in/out 或持续 memory PSI full 压力。4 GiB swap 不计作预算余量。 |
| CPU | 代表性窗口至少保留约 30% idle 余量；运行队列不持续超过 2；反复出现 steal ≥5% 或 iowait ≥10% 时暂停结论并延长观察。阈值不能只套在启动平均行上。 |
| 磁盘 | 根文件系统可用空间至少 15 GiB 且至少 20%，inode 至少 20%；还需单独计入未来独立测试目录、日志和保留周期的空间预算。 |
| 服务稳定 | 观察窗口没有新增异常重启、OOM 或持续资源压力；8787 的监听状态保持原状。监听正常本身不证明业务响应或数据完整性。 |

这些门槛不能推导用户数、每分钟任务数或模型调用吞吐；本文件不提供未量测的容量数字。若服务 accounting 不可用、缺少业务高峰或共享 CPU 波动明显，应记录限制，不补写“通过”。
