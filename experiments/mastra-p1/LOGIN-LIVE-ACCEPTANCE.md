## 员工登录与云容量

新增 `project-gateway.mjs` 和 worker：原样复制并核对 `server.mjs`、`auth.mjs`、`runtime.mjs`、`employee-gateway.mjs`、`supplier-gateway.mjs` 五份源文件，在全新系统临时目录运行。业务 `workspace-api.mjs` 被明确标记的只读身份上下文探针替代，不能把它计作整个业务 API 验收。只监听预分配的回环随机端口，禁止 8787，端口冲突即失败；原生配置不支持端口 0，实验没有宣称支持。

新增 `gateway-identity.mjs` 将 **P1 实际连接到这些原生 HTTP 登录、改密、会话和退出路由**。它拒绝自定义 origin、数据库及端口；凭据只在可信初始化过程中返回。P1 从 Cookie 取令牌后，桥接器校验真实账号 userId、原生会话及身份上下文的 member.id，并与当前只读权限适配器比较；不能把 userId 当 member.id。每次调用同步当前合成授权源，等待会话重验并检查源快照未变化。退出、停用和角色变化即时阻断，桥接器自己的会话登记仅在内存中，重建桥接器须重新登录。

可复现命令：

```powershell
node preview.mjs --synthetic --gateway-auth --prepare-only
# 保持预览，使用输出指向的私有合成凭据文件登录：
node preview.mjs --synthetic --gateway-auth
```

准备模式实际成功生成 4 条离线 mock 建议，退出并关闭自建监听器；没有创建凭据文件或模型费用。直接集成测试另覆盖两个员工的完整建议批次、跨客户 404、退出撤销、身份字段伪造、错误密码、停用后再启用时旧令牌仍失效，以及拒绝生产配置入口。

原生路由专项验证首次改密门禁、CSRF、代理头、管理员登录历史权限、供应商排斥、员工 Cookie 的 Secure/HttpOnly/SameSite/无 Domain 属性及共享合成数据库中的 Cookie 命名空间隔离。原生匿名 session 是 `200 {user:null}`；原生 login 不严格拒绝额外字段，测试验证额外身份字段不能覆盖凭据对应身份，P1 桥接入口另严格拒绝额外字段。

**边界仍保留：**目前通过 HTTP 发送模拟 HTTPS 代理头并手动回传 Cookie，没有真实 TLS／浏览器 Cookie 执法证据；loopback 代理信任不等于经过认证的代理进程。请求使用固定合成来源 IP，所有账号共享原生每分钟 60 次鉴权请求限制，不代表按真实终端 IP 的生产节流已接入。P1 新桥接器的验证使用 mock 模型；本轮收费 DeepSeek 走的是 `project-auth` 子进程认证路径，两条证据不混为一次端到端实测。生产账号、生产 Cookie、公开域名、正式数据库和实际反向代理配置没有接入。

用户已提供深圳 ECS 目标和 `default` profile。原文档位置没有 Workbench，本轮按用户提供的官方来源下载并校验压缩包，独立放置 v1.0.4 工具，没有修改 PATH。CLI 实际返回本机认证配置文件不存在；未读取凭据文件或请求将密钥发到聊天。后续用户提供了北京时间 2026-10-16 23:28:49 开始的空闲时段手动采样：可用内存约 2.9 GiB、CPU 区间平均 idle 约 98.8%、根分区可用 60G，该短窗口没有交换活动。运行服务清单也已提供；用户判断可能使用 SQLite，与当前项目源码一致，云端实际配置仍待确认。进一步提供的服务快照显示项目服务和 Nginx 均 active/running，当前内存分别约 56.7 / 6.7 MiB，所报峰值约 66.5 / 10.2 MiB，自动重启计数均为 0；三项服务级 CPU／内存限制为 infinity，父级有效限制未知。该单次快照未附时间，不替代高峰或重启增量观测。已记录 [空闲基线与容量验收](./CLOUD-CAPACITY-ACCEPTANCE.md)；助手仍未连接 ECS，采样脚本仍未在 ECS 执行。8787 监听进程归属、父级有效限制、业务高峰及同机 Agent 影响未验收，不能声称生产容量通过；继续由用户提供只读采样即可，不必向助手提供云凭据。
