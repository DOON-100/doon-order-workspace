## 实现与实际授权语义

`project-auth.mjs` 原文复制当前主线 `standalone/auth.mjs` 和 `runtime.mjs`，核对 SHA-256 后在独立子进程中执行。数据库只允许新建系统临时目录 `doon-mastra-auth-*`；校验目录、标识、原文哈希、符号链接和文件硬链接。子进程只收到白名单环境，固定自己的 `DOON_DATA_DIR`，不继承模型密钥或 `NODE_OPTIONS`，不加载主 server，不监听端口。正常关闭等待数据库句柄释放，父 IPC 断开也会清理合成认证目录。

合成账号实际执行主线 `createAccount → login → changePassword → session/logout`，并写入临时认证审计。服务端将 `session.member.id` 作为资源与建议归属；不把代表账号 userId 的 `publicSession.identity.id` 当作成员 ID。HTTP、模型与 Cookie 之外的请求字段不能选择员工。密码哈希和完整 account 对象不离开认证 worker；凭据只作为可信初始化结果和本机预览私有文件返回，不进入模型或 HTTP DTO。

账号权限的合成真源仍是内存 fixture。每次登录／会话解析把当前合成成员及客户同步到临时 SQL，再执行主线会话检查；IPC 返回后验证源快照没有变化。真实业务数据未接入，因此这不是跨生产数据库事务一致性认证。

| 范围 | 已验证的规则与实验边界 |
| --- | --- |
| 登录与会话 | 真实 scrypt、首次强制改密及旧会话撤销、12 小时绝对／2 小时空闲期限、退出、停用、持久撤销、原生失败限流和登录历史脱敏。相同临时 SQL 会话跨认证 worker 重启恢复；每次新预览使用独立库和 Cookie namespace |
| 订单 | 真实 `canRead/allowedFields` 的九角色矩阵；本人、客户分配、全读及文员兼容规则。适配入口额外要求 active 内部成员，`canRead` 本身没有该检查 |
| 客户 | 复用 `assignedServiceCustomer/customerMasterCapabilities`。订单全读不授 CRM 全读；显式成员名单优先，空名单撤权；验证严格姓名／配置别名和停用客户 |
| 团队 | 复用 `businessTeamData/filterBusinessTeamRows`。团队只筛选已授权记录；混合客户组不扩权，未知组拒绝，详情保持独立授权。实验将团队目录中的客户 ID 再与 CRM 可读范围取交集，较主线通用目录更严格 |
| 客户任务 | 复用 `customerTaskCanEdit`；须满足客户权限与该类任务的负责人／客户销售责任条件。跨客户指派不能绕过 CRM 权限 |
| 旧项目双审任务 | 复用 `canReadProject/projectTaskPermissions`；验证提交人与两级审核人的精确职责、暂停／回收／撤权／错关联。管理员不能代指定人员提交或审核 |
| 新项目协作任务 | 复用 `canReadProjectCollaboration/projectCollaborationPermissions`；内部成员被精确指派可读该条任务，但不自动取得客户或整个项目权限。无 CRM 权限时 DTO 清空客户、项目、团队 ID，且不返回描述、结果、历史或附件键 |
| 建议生成 | 预览及 P2 的 P1 真实模型入口改用主线认证适配。生成仍只接受已登录的 A/B sales；所有异步会话检查均等待完成，最后一次检查后同步重验来源并执行单员工批次事务 |

权限 loader 只允许 17 个明确列出的主线 TS 文件并记录哈希；外部依赖仅实验自己的 zod。业务 store 的写入和 workbooks 方法被替换为抛错边界，其他导入被拒绝。它测试的是实际授权函数及实验只读 API，不是整个生产 `server.mjs` 路由栈。

客户、团队和任务新增 GET 接口，所有业务 POST/PUT/PATCH/DELETE 仍为 405，附件及审批接口未开放。DTO 的 `capabilities` 仅用于核对当前项目规则，不授权实验执行对应动作。客户／任务列表最多返回 50 条及授权总数，没有完整分页，不能直接用于全量生产扫描。

独立复核发现并修复三处收尾问题：预览初始化失败时显式释放已创建资源；退出／身份切换不能吞掉后端撤销失败而报告成功；认证 worker 启动失败只有 `error/close`、没有 `exit` 时也能及时失败并清理。Windows 的正常 IPC 断开路径同时保留 `exit/close` 完成信号，防止单独等待某个事件挂起。新增故障用例使用模拟后端／模拟进程事件，正常路径使用实际子进程。

本轮没有调用 DeepSeek。既有累计账本保持 **22 次请求、保守费用 ¥0.191215**，本轮新增 **¥0**，低于用户授权累计 ¥10。账本仍采用更严格的 ¥5 限制，没有清零、换账本或提高限额。此前收费实测来自旧独立认证版本，见 [历史模型验收](./AUTH-MODEL-ACCEPTANCE.md)，不能计作新认证版本的再次实测。

## 待解决问题

1. **生产接入仍需单独设计**：尚未连接真实员工登录、生产会话、业务源或主服务路由；需要 Agent 专用授权范围、可信代理／TLS、撤销传播及来源一致性方案。本轮可证明主线源码在合成环境中的行为，不能直接替换 fixture 接业务库。
2. **新认证版本的真实模型复测尚未运行**：收费入口已适配并通过零出站预算回归，实际 SDK 链路用模拟模型验证。既有请求上限 24 次已用 22 次，双员工真实联调需预留 8 次；后续须保留累计费用后明确调整请求额度，不能新建账本绕过。
3. **写入、审批与附件授权仍未开放**：任务能力测试只计算主线规则，未执行修改或审核。真实写入仍须验收可信审批人、内容绑定、条件版本更新、事务幂等与不可变审计；附件需逐对象授权与下载审计。
4. **范围与故障覆盖**：单应用客户／资源权限不等于多租户隔离。未覆盖全部项目业务路由、持续并发、全部模型质量／恶意输入、429／断流，也未验证生产事务竞争。原生认证有持久会话但实验仍是单父进程和串行认证 worker。
5. **云环境未验收**：未接触 ECS、未评估 2 vCPU／4 GiB 的实际余量，未测试 PostgreSQL、Durable Agent 崩溃重放、真实定时触发或企业微信回执。任何云试点仍应使用独立用户、目录、端口、单 worker 和资源上限，且另行验收正式服务不受影响。

本轮没有修改业务代码，未运行完整主项目业务回归、主项目 TypeScript／build／standalone。P0 源码 5 项检查没有在本轮重跑，不计为本次通过项。
