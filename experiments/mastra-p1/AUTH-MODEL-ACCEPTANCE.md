## 身份与权限结果

| 项目 | 实现与验证 |
| --- | --- |
| 关闭自由选身份 | `/api/demo-session` 固定 404；知道员工 ID、伪造角色或身份头不能取得会话 |
| 凭据验证 | 每个实例随机分配合成账号／密码；服务端存 scrypt 哈希，常数时间比较。登录仅接受 username/password；错误凭据 401，额外字段 400 |

| 权限上界 | 仅 A/B 两名合成员工且当前角色为 sales；停用、供应商、改为 admin／finance 等均拒绝，旧会话不会因角色变更扩权 |
| 每次重验 | API、工具执行、最终建议提交均重新检查身份与当前来源权限；读取采用当前分支纯 `canRead` 函数，不加载业务存储 |

合成凭据不在页面或 HTTP 接口中公开。普通预览将本轮 A/B 凭据放在新建的唯一临时文件，终端只显示文件路径；`--prepare-only` 不落凭据。凭据文件路由 404。浏览器可视检查确认登录页不再有员工选择器、未登录不显示订单或建议；登录、退出与过期的数据清理由实际 `app.js` 的 DOM 测试及 HTTP 测试验证，未将其表述为全部浏览器的登录端到端认证。

## 建议生成的执行边界

受信入口只接收已登录 Cookie 与服务器提供的会话解析方法，拒绝自由传入 `actorId`。密码、Cookie 和身份解析逻辑不进入模型提示。模型只能调用：

1. `readOrders`：读取当前会话的授权订单白名单字段，最多一页 50 条；有后续页则停止。
2. `suggest`：提交已读来源的 ID、版本和三种允许规则之一，不能传员工、自由动作、任意写入字段或脚本。

模型提案先在内存暂存。整轮结束后，应用核对所有应有提案，重验会话、权限、来源版本及完整 DTO 指纹，再生成确定性文案并进行**单员工批次事务**。模型自由文字不保存为员工建议。任何工具拒绝、缺少提案、会话失效或来源变化均不提交该员工批次；模型吞掉工具错误也不能放行。批次内后项冲突会回滚此前插入，重复批次不增加建议。

两名员工分别提交，若 A 成功而 B 失败，A 的合成建议保留；没有跨员工整体事务。来源与账号为内存合成状态，不能把本轮校验等同于未来跨生产数据库的事务一致性。

新增安全用例实际将恶意指令放进允许读取的订单字段，再让脚本模型照做、调用跨客户工具，结果为零写入。这证明执行层拒绝该预设越权请求，不证明 DeepSeek 具备通用提示注入防御能力。

## 待解决问题和下一步标准

1. **正式身份适配**：当前是独立合成凭据系统。下一步在继续隔离的环境中适配正式会话协议，确定账号停用、撤权、会话共享存储和角色映射；完整订单／客户／团队／任务权限矩阵必须拒绝全部越权用例。不可仅把 fixture 换成业务库。
2. **模型质量与故障**：当前仅 8 条订单、4 条规则建议。需扩大合成评测、覆盖边界日期、缺字段、复杂规则、来源中的恶意内容、供应商 429／超时／断流；明确错误建议率、漏报率和每轮费用门槛。
3. **生产访问与运维**：合成服务仅 loopback HTTP，会话与登录限流在单进程内存，不是跨进程认证存储；需要 TLS、可信代理配置、凭据保管、会话撤销与监控方案后才可考虑网络试点。
4. **生产写入前置验收**：真实写接口须单独实现可信审批人、动作内容绑定、数据库条件更新／版本冲突、事务幂等账本和不可变审计；来源读取与最终写入之间的并发变化必须在存储层阻止。当前建议不等同正式任务或批准动作。
5. **云服务器与恢复**：未测试 2 vCPU／4 GiB ECS 空闲资源、正式服务基线、PostgreSQL、Durable Agent 崩溃重放、定时任务或通知回执。先只读勘察，再在独立状态目录、单 worker／并发 1 下验证资源和故障隔离，不能直接上线。
