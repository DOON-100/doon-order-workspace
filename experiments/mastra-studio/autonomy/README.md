# 后台岗位协作闭环验证

本目录是本地实验入口，验证后台任务如何唤醒岗位 Agent、通过工具传递任务，以及在普通员工工作台请求人工参与。它不启用正式调度，不接企业微信，不替换现有四岗位 Studio 配置，也不提供真实业务写入。

## 本轮链路

1. 管理员触发合成采购风险事件，服务器持久保存事项及 PMC 任务。
2. 后台 worker 领取带租约的任务，通过实际 Mastra `Agent.generate()` 执行。PMC 用通用 `submitTask` 工具提交采购核查，自己等待结果。
3. 采购调用 `requestHumanReview`，独立的中台 API 验证适配器保存指定员工的人工待办。工作台显示弹窗，持久事项直接进入已有“我的待办”列表，共用待处理/已完成/全部计数与搜索；稍后处理、读取、刷新、退出和超时均不完成待办。
4. 员工明确批准、退回或拒绝后，服务端保存本人身份、完整方案哈希、来源版本及决策，原子写入回执 outbox。Agent worker 消费回执并恢复任务。
5. 批准只确认内部跟进方案；缺口仍存在时任务持久等待时间或来源事件。实际齐货事件才允许完成采购核查并回传 PMC，PMC 再复核当前来源后结束本次风险事项。
6. 拒绝、退回、任务连续失败或人工待办超时进入总管协调任务。总管提交协调分析不代表解决原事项，原待办继续保留到本人明确处理。

不依赖员工聊天 session；每轮重新注入事项、来源、岗位目录、子任务、人工结果、观察时间与近期事件。内部岗位联系通过受控工具与持久任务进行，不使用 A2A/MCP。

## 本地启动

先在仓库根目录构建隔离的工作台，必须显式指定输出目录：

```powershell
$env:DOON_BUILD_DIR = Join-Path (Get-Location) 'test-output/autonomy-runtime-build'
node standalone/build.mjs
$env:DOON_STUDIO_MODEL = 'offline'
node experiments/mastra-studio/autonomy/start.mjs
```

前台 `http://127.0.0.1:8807/personal-tasks`，隔离工作台后端 8808。已有 Studio 8797 和正式服务 8787 均不改动。需要实际模型时，沿用服务端密钥配置并将 `DOON_STUDIO_MODEL` 设为现有支持的模型 ID；密钥不进入工作台或审核载荷。

首次仅在有 `doon-autonomy-synthetic-v1` 标记、无既有记录的专属目录创建三个人工合成身份。账号信息只保存在被 Git 忽略的 `test-output/agent-autonomy-validation/本地验证账号.txt`，不读取员工密码。管理员页面可启动事件及登记合成齐货；审核员只操作自己的待办；其他员工不能查看或处理该待办。

`DOON_AUTONOMY_DIR` 必须包含 `test-output` 路径段；测试端口可通过 `DOON_AUTONOMY_PORT` / `DOON_AUTONOMY_BACKEND_PORT` 指定。入口不会覆盖已有账号或清库，也不会自动停止占用端口的服务。

## 数据与权限

- `workspace.sqlite`：原工作台程序创建的独立合成账号库；不导入真实业务。
- `agent/platform.sqlite`：合成采购来源、人工待办、决策及回执 outbox。逻辑上模拟中台应提供的可信业务 API；正式部署必须用有鉴权的中台 API 替代，不能给 Agent 挂载正式数据库。
- `agent/tasks.sqlite`：Agent 私有任务、运行租约、工具回执、消费去重及事件。
- `agent/mastra.sqlite`：Mastra 运行轨迹，仅供管理员观察。验证入口的 Studio 只开放管理员 GET/HEAD，不允许聊天或资源写接口改变后台任务。

工作台请求每次向既有身份服务核验会话和当前角色。审批只能本人处理，模型参数不能传入身份或收件人；服务端固定映射合成审核员。审批绑定方案版本和哈希，同时复核来源指纹；来源或方案变化时旧审批被拒绝。工具只在服务器持有的任务执行上下文中生效，旧租约不能提交。

人工接口与 Agent 账本使用独立数据库，通过 outbox / inbox 去重恢复回执。覆盖“人工接口已提交，Agent 尚未关联就崩溃”的窗口。失败最多重试一次；有持久动作成功后，不因模型结束失败重新执行动作。

页面每五秒检查提醒，隐藏页暂停检查。后台运行与页面是否打开无关。员工界面沿用“我的待办”，事项和弹窗以“★ 采购助手”标明来源，悬停说明需人工确认后继续。弹窗每个身份、待办和方案版本在当前浏览器 session 提醒一次，待办入口持续可见；临时审核说明按身份与载荷指纹保存在当前 session，提交后移除。

统一列表通过 `app/personal-task-integration.ts` 的可选事件桥接入，由既有 React 组件统一渲染、筛选及计数，不操作既有任务记录。没有验证适配器发布当前身份的 feed 时，扩展为空且不产生额外网络请求。桥接只负责显示，处理动作仍交给验证 API 做身份、来源、版本及幂等检查；已处理记录只读，不能重复审批。

## 扩展岗位

`store.mjs` 的岗位目录登记 ID、能力、允许的目标岗位和工具白名单；`submitTask` 按目录统一验证，不为每对岗位增加工具。新增岗位仍须补充其 prompt、Mastra Agent 实例及处理器/模型配置，并登记可信业务事件和人工收件人映射。注册表测试演示新增质检任务可沿用统一入口；本轮没有实现在线热加载新岗位。

## 验证与边界

```powershell
node --test experiments/mastra-studio/autonomy/engine.test.mjs experiments/mastra-studio/autonomy/http.test.mjs
```

自动化测试全部使用合成数据，包括实际 Mastra 工具循环、真实 HTTP 登录/权限、跨进程重启、超时保留、回执幂等、失败重试和租约接管。离线模型是确定性脚本，仅检验链路；实际 DeepSeek 验证另行记录于本机忽略目录，明确区分程序模拟的人工决策和页面操作。

本机真实数据仅用于证据与任务路由的影子验证，未创建真实员工待办；真实记录和附件不提交。它不能证明完整生产调度已经可用。本轮总管只验证升级后的协调结果，不覆盖完整经营调度；客服登记但未完成独立业务闭环。尚需真实中台事件/outbox、审批 API、完整人工任务状态机、生产数据库并发策略、运行维护与失败告警等上线验收。
