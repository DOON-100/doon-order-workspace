# 后台岗位协作与工作台人工确认

本目录验证采购风险闭环：中台发现业务变化 → PMC 核查 → 采购方案 → 员工明确处理 → 必要时总管协调 → 协调批准后恢复原岗位 → 新一轮采购审核 → 收货证据核验 → 回传 PMC。Studio 只供管理员观察，员工使用现有工作台，无需聊天 session。正式服务默认不启用这些接口。

## 启动隔离验证

在仓库根目录执行，构建输出必须指定到测试目录：

```powershell
$env:DOON_BUILD_DIR = Join-Path (Get-Location) 'test-output/agent-chain-build'
node standalone/build.mjs
$env:DOON_STUDIO_MODEL = 'offline'
node experiments/mastra-studio/autonomy/start-chain.mjs
```

工作台前台为 `http://127.0.0.1:8809/personal-tasks`，中台后端 8810。该入口使用原生中台 API、真实业务权限和既有收货 API，只有业务对象与人员是合成夹具。合成账号保存在忽略目录 `test-output/agent-chain-validation/`，不读取员工密码；重复启动保留账号、采购记录、人工处理历史及任务状态，不重置失败现场。可使用 `DOON_AUTONOMY_DIR` 指定新的隔离目录，目录必须包含 `test-output` 路径段。端口由 `DOON_AUTONOMY_PORT` / `DOON_AUTONOMY_BACKEND_PORT` 指定，入口拒绝正式端口和占用端口。

实际模型使用已有服务端密钥与 `DOON_STUDIO_MODEL=deepseek-flash`。密钥不写入 URL、浏览器、审批载荷或仓库。旧 `start.mjs` 默认的 8807/8808 仍是单独的模拟适配器回归入口，不能当作原生中台链路的验收证据。

## 组件与联系

- `standalone/agent-platform.mjs` 属于中台：读取当前授权业务来源，只新增 `agent_*` 独立记录，包括配置、变化事件、待办、人工决策、执行前核验回执和消费确认。不会修改原采购、账号、附件或业务历史。
- `platform-client.mjs` 属于 worker：通过服务身份调用中台，私有 SQLite 仅缓存投影、范围和待消费事件。Agent 不挂载业务数据库或附件目录。
- `engine.mjs` 保存事项、任务、租约、依赖、重试、计时和动作回执。岗位通过统一的受控工具与持久队列联系，不使用 A2A/MCP，也不为每对岗位增加单独调用链。
- `runtime.mjs` 提供实际 Mastra Agent。服务器固定流程先读取事实，再只开放本轮允许的一个动作；工具处理器再次校验该动作。模型负责异常解释、核查目标和建议，不判断审批是否已通过、是否达到协调次数或能否执行。
- `agent-inbox.js/css` 为工作台人工入口。启用中台接口时，原生工作台自动加载员工组件；不依赖验证反向代理，不显示验证管理按钮。持久事项进入已有“我的待办”，共用状态、搜索与计数，用“★ 采购助手”或“★ 总管助手”标记来源。

新增岗位须登记 `store.mjs` 中的 ID、能力、允许路由与工具白名单，补充固定流程、必要的模型说明、业务来源权限及员工映射，并验证人工入口和回执。当前不支持在线热加载岗位；客服已登记，不代表客服独立业务闭环已完成。

## 唤醒、审批与恢复

中台定期观察已配置采购的最新来源指纹，原业务 POST 成功后也立即观察。变化事件及观察点在同一中台事务中保存；业务提交后观察失败可由周期观察恢复。此机制读取最新状态，会合并观察间隔内的中间变化，不是每笔业务提交的完整事务 outbox。只有管理员明确绑定的采购进入当前试验范围，不默认扫描或给全部员工建任务。

worker 消费变化事件、人工决策、审核过期事件和到期时间，按事项去重并恢复任务。不依赖员工页面在线。每轮先刷新当前权限范围；撤权范围的缓存事件不执行，也不阻塞其他业务，恢复授权后继续消费。

人工批准绑定本人身份、来源和规则版本、完整方案及其哈希、岗位轮次、协作配置及有效期。协调批准还绑定原任务、目标岗位、目标轮次和新目标。执行前中台重新核验权限、来源与有效期。核验回执仅证明执行前条件通过，实际任务恢复结果另存 worker 账本，不能把核验成功描述为业务修改成功。

协调批准仅恢复原任务并增加轮次；原拒绝记录保留，采购必须生成新的人工核验，不能沿用旧批准。协调拒绝/退回不触发自动恢复。达到三轮协调上限后生成“人工接管确认”待办；确认只记录接管，任务保持人工状态，不继续自动循环。审批、恢复、核验均不关闭采购订单、不改交期、不派生产工、不发送供应商消息。

人工待办的读取、关闭弹窗、稍后处理、刷新、退出和超时均不完成事项。提醒每个身份、待办和方案版本在浏览器 session 弹出一次，“我的待办”持续可见直到本人明确处理。来源变化的旧方案不可批准，但本人仍可拒绝或退回；worker 可用最新方案更新尚未处理的原待办，并增加版本、保留历史。审批过期不会自动算通过。

采购完成必须同时满足有效内部方案批准、当前净合格收货已齐、退货待补为零、来源未被排除，以及中台核验回执。`remaining` 已包含退货造成的缺口，`returnPending` 是其中待补部分，不可相加。PMC 收到采购完成回执后仍复核当前来源；若出现新缺口，建立新核查子任务而不重复等待已经完成的旧任务。无订单/BOM证据时不能宣称整单齐料或生产排程完成。

每次运行最多重试一次，旧租约不能提交动作。中台回执和 worker 消费记录分别持久化，支持审批提交后账本未关联、进程重启、重复回执等恢复。worker 失败现场保留，不自动清库或重置任务。

## 检查

```powershell
node --test experiments/mastra-studio/autonomy/engine.test.mjs experiments/mastra-studio/autonomy/http.test.mjs experiments/mastra-studio/autonomy/chain.test.mjs
node node_modules/typescript/bin/tsc --noEmit
$env:DOON_BUILD_DIR = Join-Path (Get-Location) 'test-output/agent-chain-build'
node standalone/test.mjs
```

测试使用临时数据库和测试端口。原生链路测试覆盖自动事件、员工拒绝、协调审批、进程重启、原任务恢复、新审核、既有收货 API、权限撤回、有效期、幂等和数量异常。离线脚本只证明程序链路；实际 DeepSeek、页面和本机数据的验证结果单独保存在忽略目录，必须明确区分合成人工处理和真实员工操作。

原生接口的配置与发布边界见 [中台接口说明](../../../standalone/README-agent-platform.md)。本地测试不启用 8787 调度，不部署、不创建真实员工任务、不修改真实来源。本机数据缺少生产订单和 BOM，当前只能验证采购证据与风险路由。正式开放仍须审核对象与人员映射、服务授权范围、进程守护和故障告警，以及中台/worker 独立发布与回退。
