## 真实 DeepSeek V4 Pro 联调

使用官方 `https://api.deepseek.com`、`deepseek-v4-pro`，固定 Mastra core 1.77.0、libSQL 1.26.1、原生 DeepSeek 适配器 3.0.52；Windows 本机 Node 24.19.0。输入和工具输出均为合成内容。

| 验证 | 结果与证据范围 |
| --- | --- |
| 普通工具调用 | thinking 开／关各 1 场景，真实模型调用只读工具并准确返回工具给出的核验字段 |
| 流式工具调用 | thinking 开／关各 1 场景，完整消费 SSE、工具结果与用量 |
| 审批暂停、批准 | 两种 thinking 均在暂停时 0 副作用；进程退出后由不同 PID 恢复相同 runId/toolCallId，批准后各恰好 1 条合成效果记录 |
| 审批暂停、拒绝 | 两种 thinking 均跨进程恢复，拒绝后 0 条效果记录且不再调用创建工具 |
| reasoning 历史兼容 | 4 个开启 thinking 的场景中，下一次实际出站请求的 reasoning 哈希与前一响应一致；包含跨进程批准和拒绝 |
| 整体 | 8 场景、12/12 子进程阶段通过；16/16 官方请求 HTTP 200，全部有可核对 usage，未重试；实际出站包含 12 次非流式 HTTP 和 4 次 SSE |

实测时间为北京时间 00:27:49 至 00:28:22，总耗时 33.081 秒；16 个请求的耗时中位数 1,229.5 ms，最大 1,848 ms。这只是小样本功能联调，不是质量评测、吞吐容量或延迟 SLA。

审批决定由测试程序模拟，未接真实员工审批身份或 UI。此处验证正常进程退出后的快照恢复，**未验证 Durable Agent 任意崩溃重放、断电或数据库损坏恢复**。

## 待解决问题与下一步验收

1. **优先接真实服务端身份**：移除／禁止生产 demo-session；由可信会话确定 actor，模型与请求体不能指定员工。使用合成角色矩阵验证未登录、跨客户、禁用、撤权、伪造身份和来源权限变化全部拒绝。完成前仍仅能作为隔离演示。
2. **将真实模型接入 P1 只读建议链路**：本次是独立协议联调，P1 仍使用 mock 模型。下一步在合成只读 API 上测真实模型的建议正确性、来源引用、成本、异常输出和提示注入；模型不能自行获得更高权限。
3. **开放任何写入／审批／附件接口之前**：先在独立合成库实现来源版本、审批人、动作内容绑定、事务幂等及审计，再以本轮攻击请求验证真正的 403／409 等业务约束；并发重复提交应只产生一条动作与一条审计。附件须用真实的合成附件授权矩阵验证。
4. **故障与费用控制**：离线 guard 测试不能替代真实 429、网络超时、SSE 中断、供应商无 usage 与崩溃恢复演练。先用注入故障覆盖失败路径，再安排有预算的供应商异常联调；生产还需全局额度和告警。
5. **云服务器只读勘察与隔离试点**：2 vCPU／4 GiB 共享 ECS 的容量尚未测量。先核对现有正式服务基线与空闲资源，再以独立目录、单 worker／并发 1 做资源与失败隔离测试。未登录或变更云服务器；本轮不构成上线许可。
