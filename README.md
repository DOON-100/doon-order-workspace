# 度昂订单协作中台

2026-09-14 文件导入试用版。网页、共享后台、权限、导入版本与报表属于同一应用。生产数据保存在 Sites 提供的 D1 / R2；浏览器不保存生产总表。本地演示数据不打包发布。

## 使用流程

1. 创建者打开私有站点并登录，首次进入成为管理员。之后只允许已授权成员进入；不会让任意登录者加入。
2. 在“成员与权限”按实际登录邮箱添加文员、PMC 和客服/销售，填写客户范围。再由站点所有者在 Sites 分享设置中开放给指定成员；仅添加应用成员不改变站点访问范围。首次发布保持创建者私有。此托管版使用 ChatGPT 登录；企业微信单点登录和内网身份系统尚未接入。
3. PMC 下载订单模板，或上传自己的工作表。选择工作表及实际表头行，确认列名映射后生成差异预览。每批最多 200 行、10 MB；支持 XLSX、XLS、UTF-8 CSV。映射的事实字段不接受公式，请先粘贴为值。
4. 核对新增、可合并、冲突和错误行。冲突默认不选择，选择后必须填写来源依据。空白不清空现值，文件缺行不删除订单。已有明细用系统明细编号，初次导入用订单/图纸/圈色/镜片/交货批次匹配。
5. 文员从“我的订单”打开明细，保存跟进、待办和附件。管理员/PMC 分配负责人，客服/销售确认对客交期。正式客户、订单数量和要求日期通过源单更正及导入维护；文员不能直接修改。
6. 后续表格协作优先导出“可回传工作表”。后台保存导出基线，导回时比较基线、总表和建议值。不同字段可合并，同一字段冲突不静默覆盖。
7. 在“上传与更新”选择 MES 包装报工。官方 lightMES 导出与带报工编号的整理模板均可导入。AC / SUN 镜片对应由操作者依据实际业务明确选择，不猜映射。未匹配保留在 MES 核对页，关联后才计数。
8. 包装报表只累计已关联且已审批的良品记录。相同来源标识重复导入不累加；更正/撤销须导入相应来源记录。未出现的记录不自动删除。本地复合标识不是 MES 原生报工 ID，期间若身份字段改变，需人工核对撤销和重建关系。
9. 文员提出 MES 更正，PMC 审核后状态为“待 MES 人工处理”。有权限人员在 MES 完成更正并重新导出；数量与建议值一致、版本更新且已审批后，才能标为“导出回读已核验”。本版不会发送 MES 写入请求。
10. 报表中心按客户/订单/负责人/进度筛选，导出客户复期、客户进度、包装明细及订单完工汇总。包装明细可按报工日期筛选。客户报表只含对客字段，未确认回复交期显示待确认。导出保存历史版本；PDF 使用浏览器打印。

## 验证范围与尚待验收

- API 集成测试以实际处理器和 SQLite 运行，16 项业务断言覆盖权限、两个身份的协作、原子冲突、旧基线、重复创建/报工、撤销、更正核验、客户导出及历史文件撤权。
- 本地浏览器验证了 XLSX 上传、字段识别、差异预览、提交总表、跟进日期、在线预计完工日期和客户报表生成；本地共享 D1 中导入 120 副测试订单及 60 副测试报工，显示部分完成。
- WebMCP 的查询和筛选工具已在可用浏览器上下文验证合法输入、错误输入和页面回读。
- 尚未用两位实际员工的独立托管账号完成生产协作验收。需成员名单、站点访问范围、完整原表及代表性文员样本。
- 未取得原订单表的完整字段、公式、下拉及提醒清单。导入保留有名的补充字段，支持显示/隐藏列和列宽调整；不能把本版视为原表所有功能已逐项复刻。
- MES / 金蝶正式接口、实时同步、自动回写尚未开通；现有每天 09:00 人工确认提醒没有被网页替换。
- 包装足量不代表完成验收、入仓或出货；返工重报、合单分摊、短装关闭规则仍需业务确认。
- 快照下载是人工归档工具，附件原文件需同时保留。自动备份、恢复演练和正式环境运维交接尚待实施。
- 当前采用整工作空间修订号协调写入，适合试用阶段；生产大批量导入及历史规模需容量测试后再提高限制。

## 开发与运行

需要 Node.js 22.13+，测试使用 Node.js 的 `node:sqlite`。依赖锁定在 package-lock.json；SheetJS 使用官方 0.20.3 分发地址，参考 https://docs.sheetjs.com/docs/getting-started/installation/nodejs/ 。

```powershell
npm run install:ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_skinny_maria_hill.sql
npm run dev -- --host 127.0.0.1
```

本地预览登录只在 loopback 生效，用于开发；不能把开发服务器暴露到局域网作为员工生产入口。正式托管依赖 Sites 认证头和访问策略。不要绕过认证直接信任公网客户端提交的身份头。

```powershell
node tests/run.mjs
node node_modules/typescript/bin/tsc --noEmit
node scripts/run-framework.mjs build
```

本地状态 `.wrangler/`、测试输出 `test-output/`、缓存 `.npm-cache/`、凭据和环境文件均不提交。数据库结构由 Drizzle 迁移管理；运行时不建表或改表。发布由 Sites 技能完成，并保持现有受众范围。

## 2026-09-14 原表协作版

新增独立路由：`/dashboard` 欠数与异常看板、`/department` 部门录入、`/completed` 已完成档案、`/receiving` 供应商收货。主页保留动态订单总表；全部页面使用同一共享数据库。

原表专用导入在 `/imports`：读取 `动态表` 第 3 行，按订单号存在的行导入，保留列编号、原值、计算缓存、源行号和原文件。数据存入 D1 / R2，真实工作簿不打包到前端、源码或静态资源中。同一文件重复导入可续传且不会重复建立记录；初次导入中的同键多行全部保留，后续原版工作簿与已有业务组合重合的记录不会自动覆盖。通用可回传工作表仍限制每批 200 行；部门日常录入可直接在线完成。

原表验收核对导入行数、订单数量及归档范围；公开源码不包含生产统计或原始工作簿。归档按用户指定范围保存，原文件不修改。

口径：欠数按订单数量减包装入仓 BF 重算，正欠数和超量分开；MES 包装报工另列，不与 BF 重复相加。阶段 WIP 为可确认上道量减本工序量，非法/负值/非整数数量不加入有效 WIP。并行路径不相加作为全厂库存。日期按上海时区；PMC 排期优先，缺失用原客户交期。原表错误缓存保留为异常提示，不继续执行 Excel 公式。参考日产能 400 仅用于页面情景计算。

部门职责：PMC AC–AF、AQ、BC；钛架 AG–AJ；外发 AK；电镀 AL–AN、AO；半成品仓 AO；胶架 AR–BA（去除自动列 BB）、BD–BE；成品 BF–BI。AP / BB 自动计算。成员部门由管理员配置；生产文员可读总表，但服务端只允许所属部门字段写入。客服/销售仍按授权客户读取。原表 CANDY/TINA 可通过成员页绑定到真实登录账号，不自动创建虚构邮箱。

供应商收货：先登记外发明细，再上传照片/PDF，人工核对供应商、送货单号、订单工序、合格/不良数量，确认后在同一事务内更新外发余欠及对应工序累计量。当前未接 OCR，照片不会自行识别；未连接 MES，不声称回写。重复照片、供应商单号、幂等请求、超外发合格余欠及跨工序部门写入均由后台检查。收货错误需 PMC 核对，当前版本没有送货单撤销界面，不应重复录单纠错。

多人工序使用版本校验，阻止旧表单覆盖新数据；源订单主数据仍通过 PMC 导入。归档/恢复需要 PMC 或管理员及明确依据，沿用同一明细编号与关联凭证。站点发布仍保持原有 owner-private 范围；添加成员后需在 Sites 分享设置中授权指定账号，未自行对外开放。

验证：`node node_modules/typescript/bin/tsc --noEmit`、`node tests/run.mjs`。设置 `DOON_TEST_ORIGINALS=1（需另行提供本地测试清单）` 额外验证本机两份提供工作簿的完整导入与数量合计。测试中的账号、凭证和订单仅存在于临时内存数据库，不写入线上。
