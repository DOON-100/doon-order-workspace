# 云端工作流自动调度（Agent 测试分支）

2026-10-19：本分支增加云端真实只读模式的后台调度实现。本次源码改动和合成验收不代表云端已部署、已配置密钥或已启用任何现有工作流。既有云端部署状态继续以 [部署记录](cloud-agent-studio-deployment.md) 为准。

## 使用和结果入口

1. 在工作流管理中设置每天、周一至周五或指定星期及北京时间，保存并发布。
2. 进入「定时任务」，核对已发布版本与数据范围，点击「启用」。真实模式发布后默认暂停；启用会创建最多 30 天、可撤销的后台只读授权，页面显示到期时间。
3. 到点后固定程序读取当前权限内的数据，按条件匹配，每条匹配记录启动一次流程。未匹配记录不调用模型；没有 Agent 节点的流程无需模型。
4. 「运行结果」显示自动运行及本次版本起的手动试运行状态，包含时间和运行编号。定时任务卡片可直接进入该流程的结果列表；自动运行的结果在页面刷新或服务重启后仍可按当前权限回读。真实模式的自由手动试运行可能读取多个来源，无法只凭触发记录证明历史输出权限，因此详细输出仅在当次页面显示，历史列表保留状态。人工审核的通过或拒绝结果会更新同一次运行。
5. 人工审核节点会暂停。拒绝走拒绝分支，暂缓继续等待；超时不会自动批准。暂停计划只阻止新的运行，已经生成的运行与审核历史保留。

修改已发布版本后必须重新启用；授权到期需核对后重新启用。启用、恢复从下一计划时间开始，不倒跑暂停期间的日期。服务在当天计划时间前已启用、随后重启或短暂不可用时，允许当天恢复后补查一次；不补跑过去日期。跨日不会自动重放前一天未决批次，须查看原运行记录并人工核对。

## 授权与运行边界

- 普通浏览器 Cookie 只在本人点击启用或暂停时用于原会话校验，不保存为后台凭据。退出登录不撤销显式后台授权；需要停用时点击「暂停」。停用账号、强制改密、撤销角色或当前业务读取权限都会阻止后台读取。
- 原生中台提供可选的 `/api/agent-schedules/*` 通道。原账号、业务记录、附件及既有权限保持原样；后台通过原 workspace GET 处理器按配置人的当前身份读取。Agent 容器不挂载业务 SQLite、附件或 Docker socket。
- 原生库仅新增 `studio_schedule_grants` 追加授权表、对应索引和 `studio_schedule_lease` 租约表，不向 `records` 写入业务数据，不修改工作区版本，不要求开启业务变更采集。无配置时不创建这些表。
- 授权绑定配置人、工作流、发布版本、源模块、数据对象、范围、条件与时间。服务只接受注册模块的只读数据通道；模型不能指定执行身份、地址、密钥、SQL、Shell 或业务写入。后台 Agent 工具进一步限制为本次触发的单条记录；人工审核恢复时同样限制查询范围。
- 后台服务使用独立随机密钥文件，浏览器、模型、轨迹和工作流记录都不接收该密钥。密钥只允许进入服务端读取闭包和内部 HTTPS Authorization 头。通道逐次检查有效授权、当前身份与权限；HTTPS 保留证书及公开域名校验。
- 原生 SQLite 的原子租约带递增栅栏编号，阻止多个 Agent 容器并行领取后台循环。租约 90 秒有效，工作期间每 20 秒续约；失去租约后停止新的读取与运行。即使某次执行结果不明，持久运行编号和回执也阻止盲目重跑。
- 每天、每个发布版本保存一次匹配批次，重试不会重新扫描成另一组记录。每条记录使用稳定投递键与运行编号，执行前重新核对来源。单批上限 100 条匹配或 2 MiB，超限整批拒绝，定时任务显示原因，不静默截断；需缩小条件再发布。
- 原生授权决定后台发现范围，服务重启无需用户先访问 Studio。用户运行时按现有哈希 schema 隔离，后台可依次释放闲置连接服务多个配置人，持久数据不删除。活跃运行时不会被淘汰。
- 带触发来源的历史运行结果每次读取重新验证来源可见性、责任归属及历史字段仍可读取；当前无权查看时隐藏，不通过旧结果绕过撤权。执行、审核、授权及历史记录均增量保留，错误只返回固定分类，不输出业务正文或凭据。

业务变更事件消费仍未在云端真实模式启用。本次只接通日历调度和内部只读结果，不新增消息发送、业务写单或自动审批。

## 后续部署配置

本次不更改 8787、云端容器、原生服务环境或现有任务状态。后续上线须分别部署原生只读桥和 Agent 镜像；原生中台最终仍跟随经检查的 main，不能为启用调度把正式服务切换到 Agent 测试分支。

原生服务需要显式设置 `DOON_STUDIO_SCHEDULES_ENABLED=1`，并通过 `DOON_STUDIO_SCHEDULES_KEY_FILE` 指向私有密钥文件。Agent 通过 `DOON_AGENT_SCHEDULES_ENABLED=1` 和 `DOON_AGENT_SCHEDULES_KEY_FILE` 读取同一独立密钥；示例覆盖文件为 [compose.schedules.yaml](../experiments/agent-server/compose.schedules.yaml)。密钥文件只在私有部署目录保存，不写入仓库、命令行、URL、镜像或日志；不要复用模型、数据库或原有协作服务密钥。

原 `/api/` HTTPS 代理转发到原生服务，Studio 继续通过原 HTTPS `/studio/` 代理到独立 Agent 容器，不新增公网端口。未部署桥、密钥不匹配或桥不可用时，页面保持未接通或失败状态，后台拒绝执行，不降级使用浏览器会话。

发布前保留代码回退点、SQLite 在线一致性快照、原件摘要、PostgreSQL 逻辑备份及现有配置。更新后核对旧记录与附件摘要，回退仅回退代码和配置，保留运行期间的新授权和执行记录；不得覆盖现库或删除卷。

## 合成验收

所有测试使用临时库、合成账号、独立端口和离线模型，不读取生产账号或调用收费模型。

```text
node tests/run.mjs
node node_modules/typescript/bin/tsc --noEmit
npm test --prefix experiments/mastra-studio
node --test experiments/agent-server/server.test.mjs experiments/agent-server/business-api.test.mjs experiments/agent-server/live-studio.test.mjs experiments/agent-server/schedule-worker.test.mjs
```

使用独立 `DOON_BUILD_DIR=test-output/agent-schedule-build` 构建 `standalone/build.mjs` 后，在同一构建目录配置下运行 `standalone/test.mjs`、`node --test standalone/agent-schedules.test.mjs standalone/workflow-trigger.test.mjs`。原生 HTTP 测试验证原登录授权、独立服务身份、退出与重启后保留、停用即时拒绝、只读源单哈希不变；工作流测试通过实际 Mastra 执行引擎和持久库验证到点执行、审核暂停与恢复、结果回读及防重。实际云端 PostgreSQL、代理配置和真实账号仍须后续单独验收。
