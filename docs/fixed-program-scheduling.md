# 固定程序定时模块

`standalone/fixed-schedule.mjs` 定义固定时间和间隔规则；`standalone/fixed-scheduler.mjs` 负责计时、持久化状态、跨进程租约和回执。供应商任务由 `standalone/supplier-catalog-job.mjs` 注册，默认关闭；启用后的默认时间为北京时间每天 07:00 一次。规则与服务器的系统时区无关。

固定时间支持设置开始时刻、每隔多少天、每天执行次数以及同一天内的间隔；所有时刻须在当天，多日频率从首次注册的北京时间日期起算。间隔模式支持设置间隔秒数及可选的累计尝试次数上限。上限按任务绑定分别保存，包含失败；未设置上限时不限制次数。已持久化的登记时间、尝试时间、租约及次数用于重启后续跑和防止重复；漏过多个时刻时只触发一次，不补发一串任务。固定时间初次注册后等待下一个时刻，间隔任务初次注册后等待一个间隔。

其他任务应通过代码注册明确的固定执行函数、独立任务状态表及租约表，配置频率和次数并明确授权范围；不接受页面传入任意命令、路径或目标地址。工作函数负责自己的权限、幂等、事务和回读验证，定时模块不替代业务验证。停止或租约失效后，业务提交仍须检查自己的租约令牌，不能把调度完成当作业务完成。

供应商任务的私有配置、实际读取范围和限制见 [金蝶供应商来源档案](kingdee-supplier-readonly.md)。后台执行不在页面显示过程；失败和耗时只记录不含业务内容的服务摘要。新增规则和测试不能视为启用真实数据任务；发布和启用须遵循项目的数据保全及权限约定。

采购未上货任务由 `standalone/kingdee-pending-job.mjs` 注册，复用上述模块。服务器私有环境变量 `DOON_KINGDEE_PENDING_SYNC_ENABLED=1` 启用后，固定北京时间每天 **08:00、12:00** 各执行一次；默认关闭，不影响供应商任务。首次启动等下一个时刻，已有登记的漏跑时刻合并补执行一次，同一时段失败不会立即无限重试。只读验收入口和供应商专用入口禁止启动。

任务使用现有金蝶只读连接和字段映射，从第一页扫描全部已审核采购单，筛出未入库/部分入库行，以账套、单据及商品行 ID 补齐独立 API 来源记录。最多读取 30,000 张采购单、100,000 条候选明细，超限或分页/身份异常整批失败。未知状态及必要字段缺失计入待核查。旧采购台账不是本表的展示来源，因此不会因旧台账存在同名行而漏掉来源明细，也不修改或自动关联旧台账。已有 Excel 来源仍按原规则去重。

沿用仅新增边界：已有 API 行原值、跟进、收货、原件和历史版本不更新；仍在未上货范围内的源行发生变化，写入独立 `kingdee_pending_schedule_issue` 核查记录。已入库、撤销、删除等退出范围的旧记录不自动移除，本任务不保证总表始终等于金蝶实时待入库余额。采购数量仍是原单数量，不推算剩余数量。核查记录及批次摘要保存在服务端，尚未增加页面核查入口。

工作函数使用明确的服务身份，提交时在同一事务内校验数据库修订号及调度租约，新增行、核查记录、回执和审计一起提交，并回读哈希；租约过期、进程停止和并发写入会阻止过期任务提交。手动同步不争用调度租约，但共享修订号与稳定 ID 防止并发重复写入，冲突批次失败后由后续操作重新核对。页面的“刷新中台”“同步金蝶总表”和 Excel 导入保持不变，手动 API 仍执行最新 30 条规则。提交代码不会自动部署、重启或开启云端环境变量。

验证：`node tests/kingdee-pending-scheduler.mjs`（合成数据），以及独立构建后的 `node standalone/test-kingdee-pending-scheduler.mjs`。
