# 客户项目读取超时修复（2026-10-29）

管理员在“全部授权组”打开客户项目开发时，项目与财务目录都可能触发前端 20 秒超时。只读查询确认项目记录仍存在，服务进程仍运行，但单核 CPU 持续繁忙；代理记录出现客户端取消请求。此记录不代表已经正式发布。

## 原因与修复

后台预读的 `framework-finance-tasks` 按订单逐个查找客户，每次又重新扫描所有客户身份、档案确认码及历史身份。后台预读被浏览器取消，也不会终止已经进入服务端的同步计算；后续项目与财务请求因此可能排队超时。

`serviceOrderCustomerKeys` 改为在单个不可变 GET 快照内建立身份到客户的反向索引并复用结果。仍保留重复档案的全部冲突声明、停用客户的身份占用、历史证据和原有歧义拒绝规则；不新增授权或自动关联。可变写入状态重新计算，新请求或重建索引不会使用旧结果，返回数组与内部缓存隔离。

共享 `data` 接口原本过滤全部审计后才保留最近 250 条，并在每条记录中重复全表查找目标。同步期间，主线 `9c8a8b1` 已提供请求内目标索引、授权后倒序取最近 250 条，以及原生快照分批让出事件循环的修复。本次安全合并并复用这些实现，追加审计回归，不重复覆盖主线方案；权限判断仍在限量之前，保留插入顺序和价格历史的敏感字段隐藏规则。

## 合成规模核验

在独立内存 SQLite 中构造 209 个客户、1,780 条订单、95 个项目、30 个成员及 15,724 条审计；所有内容均为合成数据。原实现取自本机原工作树 `0290e12`，修复后包含主线 `9c8a8b1` 及本次身份索引，因此不是本次增量独立收益。相同电脑、相同夹具的观察结果如下，属于本地单轮测量，不代表正式服务器容量承诺：

| 接口 | 原实现 | 修复后 |
| --- | ---: | ---: |
| `data` | 2,838 ms | 721 ms |
| `customer-project-data` | 1,164 ms | 514 ms |
| `project-finance-data` | 311 ms | 315 ms |
| `framework-finance-tasks` | 132 秒内未完成，停止合成工作进程 | 911 ms |

前三个接口在移除响应生成时间后，原版与修复版响应内容的 SHA-256 完全相同。原版财务任务基准未完成，不能声明该接口做过完整响应哈希对比；其身份规则由独立的原规则对照及冲突夹具验证。

新增回归覆盖 300 条较新的受限审计之后仍取得最近 250 条授权记录、管理员及客服隔离、嵌套敏感字段隐藏、历史引用、读取前后原记录不变；身份测试覆盖重复档案、历史证据、Unicode、停用客户冲突、可变状态更新及 GET 快照隔离。

合并后的完整 `node tests/run.mjs`、TypeScript 检查、独立目录构建及 `node standalone/test.mjs` 均通过。后者包含 18 项 HTTP 检查和 119 MiB 合成历史负载验证，业务记录及账号保持不变。首轮额外负载测试抽到被 Node fetch 禁止的随机端口，保留失败日志，在新隔离端口复测通过；未修改正式服务或为通过测试放宽运行规则。最终源码与 15 个构建产物的清单核验通过。
