# 订单负责人按登录名匹配

当前负责人字段统一为 `ownerUsername`，值来自账号表的 `username`，大小写归一为小写。成员姓名和邮箱只用于人员资料，不能作为订单负责人输入或推算登录名的依据。账号没有登录名时不能分配订单；空负责人不匹配任何成员。

网页负责人选择、我的订单、工序授权、批量绑定、导出、离岗交接和 CLI 使用同一字段。CLI 0.45.0 单条修改传 `patch.ownerUsername`，批量预览及保存传 `username`。旧负责人字段和邮箱值不接受。已生成的旧订单导入预览须重新预览，原批次和原件保留。

原生服务从 `local_accounts` 向成员目录提供真实登录名。发布时先准备新程序与可回退程序，保留一致性数据快照，暂停业务写入后迁移当前订单，切换程序再恢复服务。不得在旧程序仍可写入时单独迁移数据，也不能恢复旧数据库覆盖期间新增。

`standalone/migrate-order-owner-usernames.mjs` 必须显式指定绝对路径 `--database`，默认只读预览。它根据账号与成员关联转换当前订单的 `ownerEmail` 为 `ownerUsername` 并移除旧字段；缺映射、重复映射及混合字段均停止。执行需 `--apply --plan-hash <预览摘要> --backup-dir <备份绝对路径>`，先生成 SQLite 在线备份，再在事务中重核摘要并更新。订单版本、其他字段、历史审计和附件不变；新增独立维护记录并递增工作区修订号。

如需恢复已明确清空的来源负责人，可重复指定 `--restore-source <精确来源文件名>` 并提供 `--restore-username <登录名>`，仅处理这些来源当前为空的负责人。必须核对预览数量，不能依据姓名模糊匹配或恢复整库。上线后核对当前订单无旧负责人字段、登录名均对应真实账号、原审计及附件指纹未改变，并验证新接口的写入及回读。
