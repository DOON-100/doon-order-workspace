# 第一阶段实施清单：固定程序优先，人工核对关键判断

日期：2026-10-17（Asia/Shanghai）。状态：实施与验收清单，尚未执行本清单中的开发、业务操作或发布。

第一阶段先把已有确定性能力变成可靠、可核对的业务功能。能由固定规则处理的步骤继续使用普通程序；LLM 只在必要时提出带来源的候选信息，人工修改、审核后仍由同一个固定执行器处理。模型不可用时，固定功能仍应可用，不以搭建多 Agent 或完整 Agent 中心作为前置条件。

## 1. 范围、分支与运行边界

- `main` 承载固定业务功能、受控任务封装与本清单；`codex/mastra-local-validation` 保留 Agent/LLM 试验。实验分支验证通过不等于合入主线或部署。
- 8787 是正式服务；8797 是当前隔离 Studio 试验入口。端口不同只是隔离的一部分，还须隔离进程、构建、数据、附件、日志和配置。禁止测试写入正式 `lan-data`、替换 `lan-dist` 或控制正式守护进程。
- 本次只编写文档，不授权上线、启动或重启服务、调用收费模型、发送真实消息、导入真实数据或执行业务写入。
- 本阶段所有开发测试使用合成数据。生产只读核查须有明确范围；正式业务动作与部署分别按既有授权和数据保全流程执行。
- 以下工具目前是操作员 CLI，依赖目标机器的 SQLite、附件目录和已验收构建，**不是员工 API**。网页登录身份不能直接转换为本机 owner 身份；不能把脚本直接挂到 Agent、Processor、上传接口或定时任务后宣称已完成权限接入。

### 现有控制的限制

- `import-purchase-live.mjs` 内部调用预览后会继续提交，不能把它当作“员工预览按钮”；`import-customer-quote.mjs` 也没有外部演练/应用开关。
- 部分入口默认 `lan-data`、`lan-dist` 或 `test-output`，并在顶层加载 runtime、创建临时目录或输出文件。例如委外 preview 会加载可写 runtime；“preview”名称不等于全程零副作用。不得直接 import CLI 作为业务函数。
- 有些脚本选择现有 owner 身份是本机维护约定，不是员工权限委托机制。部分脚本直接事务写库，另一些调用已有业务处理器；统一封装前须逐个明确边界。
- [报价维护](../scripts/data-tools/quote-maintenance.mjs) 的演练绑定、保全和访问校验可复用，但不能推断其他旧入口具有相同保护。现有审计/导出报告仍属于私有业务数据。

## 4. 待验收：每项提供合成证据，不以“脚本跑过”判成功

- [ ] **范围和隔离**（开发、运维）：19项登记与真实文件一致；测试路径、构建、端口与正式目录隔离；不启动/停止/替换8787；测试前后正式部署路径与守护配置不因测试改变。
- [ ] **加载与预览**（开发）：模块加载无业务副作用；缺路径、错误环境、输入格式非法时拒绝；预览不修改业务记录及正式附件；需临时文件时只能写明确的隔离输出目录。
- [ ] **真实权限**（权限管理员、测试）：未登录、伪造actor、跨客户、角色不足、停用、撤权、责任转移均拒绝；审批人和执行服务权限均有效；不能沿用本机CLI的owner代行模式。
- [ ] **人工确认绑定**（业务复核人、测试）：原件、字段映射、金额/数量/单位和目标可复核；修改载荷、版本、目标或规则后旧批准失效；LLM重新生成或修改候选后必须重新审核，不沿用旧批准；未知客户/归属/数量不得自行补全或默认为零。
- [ ] **未批准不执行**（业务复核人、测试）：对需要审批的动作，人工拒绝、暂缓、审批超时或未回复均不产生业务执行；时间流逝、模型重试或自动补跑不能转成批准。已进入执行但结果未知的情况另按回读核验处理，不伪装为尚未执行。
- [ ] **并发与幂等**（开发、测试）：重复提交、重复批准、同键不同内容、旧版本、执行超时和进程中断不造成重复效果；结果未知先回读核对，再决定补做哪一步。
- [ ] **保全和回读**（开发、业务复核人）：只改变批准范围；旧记录、主键、关联、历史版本、附件和账号权限保全；回读值一致才记成功；报告只公开摘要，不提交私有快照。
- [ ] **无模型可用性**（开发、业务复核人）：不配置模型、模型超时或返回非法候选时，固定表单/检查/执行仍可完成；候选不能直接写入或获得审批。
- [ ] **测试与发布分离**（测试、运维）：代码改动按项目规则执行相关合成测试，新增场景验证上述缺口；记录测试范围和失败项。另行满足发布授权、在线一致性备份与回退准备后才考虑上线；Git同步不是部署。

本轮仅完成清单、代码及文档只读核查，没有运行这些验收。既有测试文件证明有测试入口，不代表本轮重跑通过，也不证明真实员工使用或生产性能已验收。

## 5. MES / 金蝶：只读核验和固定例外处理

已有历史线索称金蝶新建销售订单可传到MES，但同步方式、当前运行、字段完整性以及变更/取消覆盖仍需只读核验。中台文件导入、网页链接或历史导出成功不能证明ERP/MES数据库直连或实时接口已打通。

- **待核验，负责人：ERP/MES管理员与业务复核人。** 明确实际产品、数据来源、原生标识、订单与明细关系、更新/撤销口径和近期同步证据；记录观察时间及权限范围，不推测接口。
- **待整理，负责人：数据对接开发。** 本机独立 `automations/mes_writeback` 不在本仓库目录内；仅把已确认来源、固定字段映射、四键/稳定明细匹配、幂等与异常清单作为后续评估输入，不直接启用旧写入目标。
- **待验收，负责人：业务复核人。** 镜片映射未知、同键多行、同键多次报工、来源日期不完整、撤销或更正不明时交人工确认。MES包装良品与仓库入仓分别核算，不能自动等同或重复累加。

本阶段不启用MES写回、不接管既有金蝶→MES链路，也不把模型判断作为入仓或同步成功依据。

第一阶段完成的判据是：选定固定功能在正确权限下可预览、可审核、可追溯执行并回读验证；未知项留给人工，模型缺席不影响核心流程。后续是否引入Agent，依据实际剩余的非标准判断工作与合成评测收益决定。
