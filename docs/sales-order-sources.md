# 销售原单明细资料

在“客服与单证 → 中英内部订单”顶部查看“已导入销售原单”。每张原单独立显示订单号、客户、原款号、图纸编号、色号、原 SKU、数量、单位、样办、来源单价和交期原文。点击明细行查看颜色栏目与标准标题，以及原单元格、合并锚点、隐藏列、公式和缓存值。

## 数据边界

- 资料保存为独立 `sales_order_source`，状态固定为“待核对”，不创建 `order`、内部生产单、报工、库存或 ERP/MES 指令，不进入现有 PMC 生产数量汇总。
- 数量按原单位分别显示；样办数量独立，空白不替换为零。颜色按来源列保留，允许多列对应同一标准字段；组合值不拆分，候选不自动采用。
- 文件名称、SHA-256、工作表和明细范围用于追溯。该接口登记结构化来源资料，不上传工作簿附件、图片或其他工作表。原文件应在私有存储中保全。
- 原单价、历史日期或订金公式不等于价格审批、交期承诺或收款。正式开单、生产单转换和 ERP 推送需要另行明确字段、单位及业务确认流程；当前面板没有发布动作。

## 接口与权限

- `GET /api/workspace/sales-order-sources-data`：管理员可读取；其他在职内部人员需唯一客户档案及已有业务/客服责任关系。生产总表访问权不自动授予销售原文和价格权限。响应沿用当前业务组筛选。
- `POST /api/workspace/sales-order-sources-import`：仅在职内部管理员，参数 `{token, source}`，请求上限 8 MiB。字段合同见 `lib/sales-order-sources.ts`。
- 同一请求标识和完整内容重试返回原结果。同客户、同订单、同来源及相同内容的新请求不会新增资料；不同内容返回冲突，不覆盖原记录。
- 来源、请求回执和审计一次提交，使用既有鉴权、同源检查及修订号并发控制。通用审计流不暴露销售原文快照。
- 真实客户资料、导入脚本、请求与回执只保存在仓库外的私有目录；公开仓库仅保留通用功能和合成测试。

## 验证

`node tests/sales-order-sources-cases.mjs` 检查权限、数据隔离、去重、冲突、字段及请求上限；`node tests/run.mjs` 包含同一接口验收。浏览器验收使用独立临时数据库和合成原单。
