# 账号人员类型

成员的 `personnelType` 为 `internal`（内部员工）或 `external`（外部人员），独立于管理员、PMC、销售、财务、程序员等业务角色。管理员可在创建账号及编辑成员权限时设置；“账号与密码”表在姓名旁显示该类型。

兼容旧账号的规则经用户确认：供应商始终为外部人员，其余缺少此字段的既有成员按内部员工解释。读取旧成员不批量回写记录；新建及经管理员保存的成员明确记录类型。旧客户端未提交该字段时保留既有分类，非法值拒绝保存。分类调整不修改账号主键、密码、岗位角色、业务授权、附件或历史记录，成员保存沿用原审计。

中台 `/api/auth/session` 返回服务端计算的人员类型。Studio 对每个请求重新核验当前会话，只接受启用、已改初始密码、明确返回 `internal` 的账号；所有内部业务角色均可进入。外部账号、供应商和缺少类型的上游会话均拒绝，不能通过页面入口、API、静态缓存或既有后台授权绕过。账号改为外部后，下一次请求及后台授权核验立即拒绝；个人 Agent schema 与历史记录保留。

Studio 的准入不增加订单、客户、部门或业务执行权限。工具仍调用中台原有有鉴权接口，业务范围及人工审核规则保持原样。

合成回归：`node tests/run.mjs`、`node standalone/test-personnel.mjs`、`node standalone/test-personnel-browser.mjs`、`node --test standalone/agent-schedules.test.mjs`；浏览器测试使用独立目录和测试端口。Agent 测试分支另验证入口、逐次会话、跨账号存储和后台授权。
