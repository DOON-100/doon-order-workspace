# 流程变更人工确认接口

固定程序接口，复用原 `process-save` 的字段、关联、客户／订单、负责人及完成条件校验。适用于现有 14 类流程记录的新建与修改，不提供物理删除，也不代替财务记账、ERP 库存或实际出货放行。

| 接口 | 行为 |
| --- | --- |
| GET process-change-contract | 协议、当前校验规则指纹及有效期 |
| POST process-change-preview | 创建独立的 `process_change` 预览；不改业务记录及历史 |
| GET process-change?id=UUID | 仅本人在当前维护权限内读取预览和执行结果 |
| POST process-change-confirm | 本人明确确认所见摘要；服务端校验后原子保存 |
| POST process-change-cancel | 取消尚未执行的预览，不撤销已经保存的业务 |

路径前缀均为 `/api/workspace/`。写请求要求有效登录及严格同源 Origin。预览请求只接收程序生成的 UUID、当前规则指纹、原接口允许的完整字段及依据；不接收操作者、业务幂等 token 或自行声明的权限。

预览保留完整载荷、原记录、来源说明与位置、未知项、冲突、创建人和 30 分钟有效期。摘要绑定以上信息，并绑定目标流程记录、客户、订单、小组及相关负责人当前记录的哈希。其他无关业务变更不会使预览过期。自由文本引用及外部文件说明仍须本人核对，不能把其文字当成程序已经验证的证据。

确认只接收 `{id,digest,approved:true}`。不能附加字段覆盖原预览；内容要调整时取消旧预览后重新生成。存在未知项或冲突、超时、取消、来源变化、角色／客户权限变化、规则变化或原版本变化均拒绝。规则指纹来自实际字段定义和确定性校验代码，发布新规则后旧预览不能静默沿用。

业务记录、业务历史、原审计、预览完成状态和独立执行审计在一次 `commit` 事务内写入。并发请求通过工作区版本保护；同一已完成预览重查或重提仅返回原回执，不新增业务记录。回执记录真实身份、记录编号和执行版本，并校验完整性。回读也重新校验当前权限；无法读回时不能宣告保存成功。

此实现没有部署。`tests/process-change.mjs` 使用独立内存数据库与原 API 路由，覆盖 14 类型预览、身份与同源、字段绑定、版本／来源变更、过期取消、事务失败、并发重复请求、结果核查与原数据／附件字节保全；已加入 `tests/run.mjs`。测试辅助程序只创建受校验的 `test-output/process-change-*` 目录。
