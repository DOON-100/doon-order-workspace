# Agent 流程变更确认接入

本轮接通十组工具中已经适配的 14 类流程新增／修改：Agent 提出完整字段，当前登录人打开预览核对并确认，中台固定程序校验、保存、回读与留痕。采购、生产、管理等尚未适配动作及删除仍不开放；没有部署，也没有改正式数据、账号或运行配置。

## 使用流程

1. Agent 调用原部门工具的 `prepare`。工具逐次验证当前身份、原记录和可编辑字段。
2. 启用接入时，程序生成请求 UUID，向中台登记独立预览，返回“核对并确认变更”链接。业务尚未修改。
3. 本人打开预览，核对完整字段、关联记录名称与编号、修改前值、依据位置和未知／冲突项。需改内容时取消后回到对话生成新预览。
4. 勾选并点击确认后，中台重新校验权限、来源、规则、版本及 30 分钟有效期；在同一事务保存业务、历史、审计与执行回执。
5. 页面通过独立 GET 回读记录后显示结果。响应丢失或回读失败时显示待核查，只允许查询原请求，不自动重发写入。重复确认已完成请求只返回原回执。

模型只获得登记预览的方法。确认／取消处理器保留在受信任 HTTP 会话中，不进入工具上下文。后台事件不能登记此类业务草稿。来源文本仍需人工核对；系统不会把模型给出的引用视为已验证事实。未知项、冲突、过期、权限或绑定来源变化会阻止执行。

## 配置和发布边界

功能默认关闭，仅当 Agent 的 `DOON_AGENT_PROCESS_CHANGES_ENABLED=1` 且使用真实业务模式时启用。本次未设置该变量。中台需先具备兼容的 `doon-process-change-v1` 接口：`process-change-contract`、`process-change-preview`、`process-change`、`process-change-confirm`、`process-change-cancel`。旧中台或不兼容协议返回错误，不退回直接写入。

中台固定接口在 `main` 独立交付；Agent 运行时、预览页面及镜像白名单仅在 `codex/mastra-local-validation`。两者独立发布。Agent 通过固定 HTTPS 路径和原会话访问中台，不挂载业务数据库或附件目录。确认页面与 API 继承 Studio 登录保护，写请求严格核对 Origin。

原部门接口清单继续固定在已审核的 359 项基线；新增五个接口属于应用控制层，由固定客户端调用，不能登记成 LLM 确认工具。本地草稿校验后，中台再按实际规则校验完整载荷，并绑定自己的规则指纹；执行时不接受旧预览静默跨规则版本使用。

## 合成验证

从 Agent 工作树执行，参数指向包含本轮固定 API 和测试辅助程序的中台源码目录：

```powershell
cd experiments/mastra-studio
npm run test:process-changes -- --middleware-root <中台源码工作树>
```

测试使用独立内存数据库、合成账号与 Cookie、隔离 Studio 存储及临时端口。真实中台 API 路由与 Studio 页面协同运行，覆盖预览、人工确认、取消、身份撤销、禁止模型确认、重复请求及保存后响应丢失。设置 `DOON_PLAYWRIGHT_MODULE` 为本机 Playwright 模块绝对路径时，还会用本机 Chrome 检查按钮、执行及查询状态，并保留截图于被忽略的 `test-output/`。

中台另有 `tests/process-change.mjs`，覆盖 14 类型、事务回滚、并发、来源绑定、过期与原记录／附件字节保全，已纳入中台业务回归。所有这些验证不接触正式业务，也不调用外部模型。
