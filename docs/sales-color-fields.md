# 销售颜色字段库

“中英对照内部订单”（`/factory-orders`）内增加可折叠的字段库。业务和客服可查找标准中文、英文以及获授权客户模板的原栏目，查看对应规则并复制标题。名称近似时只显示候选；已明确的模板别名使用已配置对应。输入查询、选择模板、复制标题均不写订单。

字段库是标题配置，不是颜色值字典。原色号、板料码、斜杠占位、空白、实际颜色描述及历史内部单保持原样。不同来源栏目可引用同一标准字段，但来源栏目ID及部位限定独立保存。组合栏目保留完整源结构；未定义拆值规则前不展开为多个实际值。现有032R2模板中的颜色值翻译逻辑保持原样。

## 数据与权限

- `GET /api/workspace/sales-color-fields-data`：返回当前版本、标准标题及当前成员可读的客户规则。业务组筛选只缩小客户规则范围。供应商和停用成员不能读取。
- `POST /api/workspace/sales-color-fields-save`：仅现有管理员可提交 `{version, token, catalog}`。服务端严格校验配置结构、引用、重复ID、组合状态及版本；相同请求标识仅允许相同人员和相同内容回放。
- 每次保存追加 `sales_color_field_catalog`、审计和请求回执，不覆盖旧版本，也不写已有订单、MES记录、附件或账号。不能用经过筛选的局部目录静默删除旧字段、客户规则或来源栏目。
- 配置保存在受权限控制的数据库，真实字段原表、客户模板、上传载荷及一次性维护脚本不得提交公开仓库。新增目录不能扩大客户责任或账号权限。

`catalog` 包含 `schemaVersion: 1`、`title`、`dictionaryVersion`、`sourceSha256`、`fields` 和 `profiles`。字段含稳定ID、中英文名称及来源单元格定位；客户规则按客户、产品和来源工作表保存独立来源栏目。文件行号只是来源定位，新增版本须沿用稳定ID。配置不承载订单数量、价格或实际颜色值。

字段还可保存原中英文名称、历史别名及已核实的金蝶同义栏目证据。可选 `orderFields` 独立记录订单基础字段的统一名称，不把数量、价格或客户编号混入颜色部位目录。更新名称须保留旧名称的查询入口；历史目录版本及原单快照继续保留。原单读取接口只返回已授权原单所需的名称覆盖，不返回额外客户规则或商业明细。

字段库展示统一名称、原名称、来源及金蝶对应列。没有对应列的颜色专用字段保持原名；不能用一个泛化的“辅助属性”代替多个部位字段。名称相同不等于单位、客户或商品编码已完成值映射，ERP 导入须另行校验模板必填项与业务状态。

## 匹配

纯函数 `matchSalesColorField` 先核对选定客户规则和来源栏，再查询字典名称。双语表头按已配置换行别名查找，同名命中多个栏目时保留候选。英文重复不能合并两个中文部件；模糊相似度不会自行变成新的已批准映射。程序不改写查询来源或订单值。

## 验证与上线

运行 `node tests/run.mjs`、`node node_modules/typescript/bin/tsc --noEmit`；独立匹配与权限回归为 `node tests/sales-color-fields.mjs`。内网构建写到独立 `DOON_BUILD_DIR`，使用临时数据运行 `node standalone/test.mjs` 和颜色字段浏览器验收。

正式上传分为代码更新和独立配置保存。代码更新按[发布保全说明](code-only-release.md)验证构建、保存一致性备份并核对既有记录和附件。配置提交前核验来源摘要和完整载荷，提交后通过API读回核对并保存原数据不变的记录。配置读取成功不代表销售原单已导入或ERP/MES已接通。
