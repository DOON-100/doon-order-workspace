# 金蝶采购订单一键同步

本文描述手动入口，其最新 30 条规则保持不变。独立后台定时任务复用固定程序模块，启用后于北京时间每天 08:00、12:00 全量扫描并同步当前未上货明细；配置、数据保全边界及验证见 [固定程序定时模块](fixed-program-scheduling.md)。

入口：供应商管理工作台或采购未上货订单总表，点击「同步金蝶总表」。页面已移除 Excel 上传与确认导入入口；当前总表只展示 API 最新明细；旧 Excel 不再拼接进入当前表。直接执行，没有预览或二次确认；一次点击只执行一个有上限的批次，不创建定时任务。按钮出现时仅提前准备并缓存金蝶令牌，不读取订单或写入中台；点击时复用令牌，同进程并发准备合并。按钮文字和占位保持不变，仅图标旋转并禁用重复点击；进度、结果和错误通过页面顶部 Toast 显示，每条显示 5 秒后自动消失，新消息替换旧消息，不挤动按钮或表格。

## 同步规则

用户于 2026-10-31 明确要求：定时全量同步，手动仅同步最近 30 条，采购未上货只保存金蝶最新明细，不再累计旧版本。

- 金蝶业务接口只读。中台按“账套 ID＋单据 ID＋行 ID”更新独立 API 来源缓存，旧采购台账、跟催、收货、账号和附件不是更新目标。
- 手动入口沿用原窗口：已审核采购单按创建时间倒序展开，先排除全部入库和未知入库状态，再选最近 30 条未入库 A／部分入库 Z 明细。选满或到列表末尾即停；已有行更新字段，不向更早记录补足新增数量，窗口外缓存不删除。每页 30 张单据，详情最多三路并行，仍校验分页数量、顺序和身份。
- 已有行逐字段比较，发生变化直接替换当前值；无变化不重复写明细。旧台账与 Excel 的模糊匹配不再抑制 API 行。数量仍使用原单 qty，交期使用 delivery_date，客户订单关联未核验时留空。
- 定时任务从第一页扫描全量已审核采购单，完整成功后更新当前待入库集合，并删除该账套已退出集合的 API 缓存行，包括全部入库、撤销审核或从完整结果消失的行。其他账套和原业务记录不受影响。
- 全量扫描遇到网络、分页、身份、未知入库状态或必要字段异常，整批失败，不更新或清理当前表。手动窗口内不完整行计入待核查，不以猜测值覆盖。上游分页读取不是金蝶账套的原子快照。
- 读取期间若另一个同步已经改变采购来源，本次拒绝覆盖；其他业务更新可在再次读取修订号后继续。提交时统一校验修订号；定时任务另校验现有租约。新增、更新、删除、成功时间和结果回执在同一事务中保存并校验，失败整批回滚。
- 请求 ID 绑定已完成的事务结果。重试读取回执，不依赖已被后续同步更新或删除的旧行，也不重新执行旧批次。只留运行数量摘要，不新增旧明细副本或字段变化历史。
- 页面当前表只展示 API 最新明细，不拼接旧 Excel；空的全量成功结果仍显示零条，不能回退展示旧快照。每次成功（包括零变化）更新“最近成功同步时间”，另显示“最近全量同步”和本次方式，避免把手动窗口时间当作全表覆盖时间。
- 仅有效 PMC／采购和管理员可手动同步；小组范围请求仍拒绝，读取沿用原采购权限。旧 Excel 原件及显式历史查询仅保留兼容，不参与当前 API 表。

## 服务器私有配置

默认关闭，未配置时点击按钮提示连接未配置，不调用金蝶、不写入中台。原生服务通过进程环境读取以下变量；云端运行时使用同名私有 binding / secret：

| 变量 | 用途 |
| --- | --- |
| `DOON_KINGDEE_READONLY_ENABLED` | 值为 `1` 才启用 |
| `DOON_KINGDEE_CLIENT_ID` | 目标应用 ID |
| `DOON_KINGDEE_CLIENT_SECRET` | 应用 Client Secret；与企业 appSecret 不同 |
| `DOON_KINGDEE_INSTANCE_ID` | 明确指定正式企业授权实例，不能沿用沙箱实例 |
| `DOON_KINGDEE_ACCOUNT_ID` | 固定目标账套 ID，不默认选第一个账套 |

密钥应由管理员通过私有运行配置或凭据管理器注入。不要放在命令参数、URL、网页输入框、仓库文件或日志中。Windows DPAPI 加密配置不能直接在 Linux 使用。不要因提交代码自动修改生产配置或重启服务；正式启用按项目发布及备份规则单独执行。

授权材料需同时匹配应用、实例、账套和有效状态，且恰好一个匹配；路由来自授权响应并限制为 HTTPS 的金蝶 `*.jdy.com` 域名。令牌仅在服务端内存缓存 23 小时，凭据改变会失效；同进程并发鉴权合并，失败后限制再次请求频率，不盲目刷新重试。服务多实例运行时，每实例各有缓存，应另行评估金蝶令牌接口限流。

只有以下固定金蝶调用：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/jdyconnector/app_management/push_app_authorize` | 获取企业授权，空请求体，不提交业务单据 |
| GET | `/jdyconnector/app_management/kingdee_auth_token` | 获取令牌 |
| GET | `/jdy/v2/scm/pur_order` | 查询已审核采购订单 |
| GET | `/jdy/v2/scm/pur_order_detail` | 查询采购商品行 |

应用侧接口：

- `POST /api/workspace/kingdee-sync-run`，只接受 `{requestId: UUID}`，服务端固定范围与 30 行上限；不接受浏览器提交的源行、页码或数量上限。
- `GET /api/workspace/kingdee-sync-ready`，仅准备连接，校验相同角色与全表范围权限，不返回令牌、不读取采购订单、不写业务记录。
- `GET /api/workspace/kingdee-sync-result?requestId=UUID`，只回读当前操作人的批次结果，不重新同步。
- 保留 `GET /api/workspace/kingdee-readonly-status` 和 `GET /api/workspace/kingdee-readonly-query?page=1&start=YYYY-MM-DD&end=YYYY-MM-DD` 供只读诊断。状态接口只检查配置，不代表网络成功；只读查询不写中台。

回执返回新增、更新、无变化、待核查、选取数量、详情中全部入库排除数、入库状态不明未纳入数、源查询截止时间和处理耗时；不再显示历史页码或提示继续下一页。凭据、令牌、联系方式、价格和上游原始错误不进入响应与日志。运行变量中的 `READONLY` 指金蝶业务访问方式，不禁止已授权的中台当前缓存同步。

## 开发验证

`node tests/kingdee-sync.mjs` 覆盖最近 30 条窗口、同 ID 字段更新、窗口外保留、旧台账及 Excel 不抑制 API 行、零变化时间更新、历史回执重放、并发与回滚、权限和原业务保全。`node tests/kingdee-pending-scheduler.mjs` 覆盖全量替换、整单及单行完成、来源消失、空集合、其他账套隔离、失败不清理和事务内校验。`node tests/run.mjs` 包含上述专项。
