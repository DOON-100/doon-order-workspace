# 客户项目跟进人筛选

项目清单的“指定跟进人”按该项目所有未完成事项的实际跟进人筛选，保留逐人多选、跨列组合和零结果提示。筛选不会改变事项负责人或任何访问权限。

只有明确指定的人员可以作为“尚无事项”的额外筛选候选，不能默认加入全部员工。部署页面可用 `customer-project-extra-follower-ids` meta 的 `content` 配置 JSON 成员 ID 数组。发布工具写入 HTML 属性时须正确转义；配置缺失、格式错误或空数组时，不添加额外人员。配置还须与当前已授权返回的启用内部成员取交集，不能因此暴露未返回的人员。

实际人员 ID 只保存在私有发布配置和服务器回退材料中，不写入公开源码或测试。后续发布必须保留已批准的该项配置，不能按全员名单重新生成。新增待办继续使用既有候选接口和服务端授权，此配置只控制清单的额外筛选候选。

专项检查：`node tests/customer-project-list-filters.mjs`；隔离浏览器验收：设置 `DOON_BUILD_DIR` 后运行 `node standalone/test-customer-project-assignee-browser.mjs`。测试只使用合成人员和临时环境，验证已有跟进人加一个明确指定人员，其他未分配人员不进入筛选。
