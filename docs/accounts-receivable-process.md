# 应收账款业务流程

财务应收工作空间集中查看原发票、历史收款核对、付款凭证与客户对账单。历史总表先形成可追溯的档案；存在差异的记录保留待核对。后续业务逐笔登记，避免每月重新覆盖历史总表。

## 当前功能与待接入流程

当前历史档案提供原件归档、解析包预览导入、来源定位、独立备注、付款凭证补传、累计实收核对与冻结 STATEMENT 草稿。历史档案独立展示，不生成实际现金，也不混入现有正式余额。新到账、用途分配、退款和冲销继续使用已有客户项目财务入口。

订单 PI 与商业发票自动归集到同一应收义务、历史期初正式切换、历史核销反向更正及跨票到账的统一入口仍待接入。凭证归属客户级到账后供多票引用、凭证撤换的版本管理也是后续联动目标。下文“日后新增业务”描述完整业务顺序，不能视为这些自动联动已经完成；未接入部分继续保留原记录和来源说明，不通过修改备注改变账务。

## 历史导入

1. 为每个客户提交发票及 STATEMENT 历史总表，注明客户代码、币种、发票截止号、对账截止日。文件名中的日期不能自动作为对账截止日。
2. 原文件保存一份不可变原件并记录 SHA-256。解析包记录每条数据的工作表、单元格、原值与疑点。先预览再导入，重复文件不会重复建档。
3. 发票号按客户识别，保留同号的所有版本；缺原票时只保留对账单依据并注明缺件。PI、商业发票、订金通知、贷项通知不可混为同一种债权。
4. 检查逐票金额、分期应收、累计实收、未收及合计。累计余额列不能当逐票余额。没有票号的款项进入待分配清单，不能按相邻行或先进先出自动认定。
5. 订金通知的已收金额与后续发票扣订金关系必须成对保留。原发票面额与历史净应收分别追踪，避免一笔订金和含订金的整票重复计账。
6. 核对历史累计实收时填写依据和金额，由系统计算未收与状态；不创建缺少真实到账日期的现金流水。超过应收、同号多版本确认、已有正式应收重复等情况由服务端阻止。
7. 生成客户、币种、截至日对应的 STATEMENT 草稿。未知金额显示待核对，不按零汇总；同号版本不重复累计。未核对项、缺件与源表差异随快照保留。核对完成后才能用作对客定稿。

## 日后新增业务

|环节|负责人|输入与操作|下一环节的依据|
|---|---|---|---|
|客户建档|业务、客服|确认客户代码、付款主体、币种、责任组及授权付款条件|唯一客户与条件版本|
|PO与报价|业务、客服|录入客户PO，关联报价、SKU、数量、价格与条款|已确认订单版本|
|PI及应收计划|客服制单、业务审核|从订单生成PI；审核并正式签发；按约定生成订金及尾款计划|唯一应收义务、组别与条件快照|
|订金到账|财务|登记实际到账日、币种、金额、账户、流水号及凭证，核销到对应应收|已核实收款及核销关系|
|生产与出货|PMC、仓储|引用已确认订单，记录实际出货批次、日期及数量|实际出货证据|
|商业发票|客服|按出货批次和已核对价格生成CI；关联原PI应收义务|发票与应收的对应关系|
|尾款或合并付款|财务|一笔到账可分配多票，一票可接受多笔到账；未分配款留客户账上|核销记录及剩余可分配金额|
|对账与催收|财务、客服|按客户和原币生成STATEMENT，确认差异、到期日及催收记录|冻结对账版本与客户反馈|
|结清及归档|财务|未收为零自动显示已收款；保留原票、核销、凭证、调整及审计|完整历史档案|

已有项目 PI 支持审核、签发及收费计划。订单 PI 与商业发票自动归集仍需按唯一应收义务逐步接入，不能把资料审核状态当成财务入账。现有客户项目财务提供实际到账、用途分配、退款及冲销入口；历史发票档案的累计实收不参与本期现金业绩。

新客户首次迁移继续使用历史导入；上线后的新发票应由订单或出货生成。暂时无法生成的外部发票使用增量导入，只增加新号或保留新版本，不重置旧账。发票修改通过版本、差额或贷项处理，已核对的旧版不覆盖。

## 付款凭证与已收款备注

“上传付款凭证”保存银行回单、客户水单或其他证明，记录上传人、时间、文件校验值及说明。补传文件不会自动增加实收，也不表示银行已到账。历史缺证记录可以显示“历史对账单核对已收，凭证待补”。

后续统一到账流程中，新收款先形成客户级到账，再分配至发票；凭证归属于这笔到账，多张发票引用同一凭证。当前历史档案的凭证补传仅补充核对依据，不建立该客户级到账联动。客户水单与银行到账确认应分别保留，金额、日期或币种不符时保持待核实。后续凭证撤换功能须保留版本历史，不删除旧原件。

收款状态由金额计算：未核对、未收款、部分收款、已收款。金额为零的发票和贷项需独立核对，不凭备注认定收款。系统生成的收款说明与人工业务备注分开，避免修改备注造成账务状态变化。

## 对账口径与例外处理

- 当前应收余额、历史累计收款、本期实际现金、实际出货金额分别呈现，不能相加作为一种业绩。
- 各币种独立对账；不自动换汇或跨币种核销。高于两位小数的原始金额保留原值，舍入口径须核对后确认。
- 逾期只根据有效的到期日计算。缺少付款条款、计划出货日或实际出货日时显示待触发，不能自行推定账期。
- 溢收保留未分配客户款，不能强塞入已结清发票。银行手续费、折扣、退款、坏账及贷项是不同业务类型，需有独立依据和审核。
- 既有项目财务的退款、冲销继续由原入口办理，真实退款保留退款日期并影响该期现金。历史档案的核销反向更正仍待接入；目标流程通过反向记录更正，不删除原收款、原票及凭证。
- STATEMENT 保存生成时的金额、原单版本、截至日与差异清单。后续付款生成新版本，不回写已发送的版本。发送客户前由客服与财务核对收件人、金额和附件；系统不自动外发。

## 分工与权限

客服维护原票、PO与出货关联并跟进客户差异。财务确认到账、核销、退款及对账口径。业务负责人确认合同与价格变更。管理员管理授权及历史迁移，不能以管理员身份替代来源事实。

本次历史档案写入沿用已有管理员权限；未扩大财务或业务账号权限。财务正式操作范围应使用已有授权机制按客户、组和职责配置，只读账号不得写入或上传。历史归属保留发生时快照，不随客户当前分组倒改。

## 上线与验收

上线前保存一致性数据库快照、附件校验清单及代码回退点。新实体增量保存，不覆盖生产订单、原票、账号及权限。代码回退不能把业务数据库恢复到旧状态而丢失期间新增。

验收包含重复导入、同号多版本、未知金额、部分收款、超额核销、跨客户与只读权限、凭证补传不计现金、历史核销不计本期业绩、对账快照冻结、并发版本冲突与原记录保全。历史差异核清后再确定正式期初切换日，后续现金按真实发生日逐笔办理。
