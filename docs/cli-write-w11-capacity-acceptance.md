# W11 隔离读取负载与权限核验

2026-10-28。测试环境，不含正式业务数据。原生服务仅监听随机loopback测试端口，SQLite、附件及会话全部位于新建临时目录，未访问8787、正式数据、银行、ERP或真实邮件。

使用CLI的进程内API客户端和真实原生处理器；两个合成账号中，一个仅有C2项目权限，另一个没有项目权限。独立增加1000或5000条最小合成项目，分别核对授权账号总数1001/5001、无授权账号0。每个并发档24次业务查询，两个账号交替；前置、负载及跨项目拒绝合计76次固定GET。每次核对总数及分页ID集合，读取前后业务记录和原附件逐值/字节相同，退出清理测试目录。

每档一半查询返回授权项目，一半返回空授权结果；分页输出最多100条，服务器仍读取既有完整数据。5000条、8路时出现约3秒最大查询，不能把客户端分页当作后端容量优化。以上是同一Windows机器的一次观察，同机同时运行其他合成检查，包含竞争噪声；没有生产网络、TLS代理、真实附件规模或持续写入负载。

这里的8路不是8名员工，只有两个合成账号；未测并发Windows进程启动、真实DPAPI开销、正式服务器硬件、混合读写或长期稳定性，不能据此承诺接入人数或SLA。后续正式容量验收需要明确代表性数据量、请求组合、延迟目标、机器与代理限制。现有全量目录接口可另行评估服务端分页，不能在本次测试中擅改业务规则或部署。

复用方法：在仓库根目录运行 `node cli/tests/integration/sales-api.mjs --development-cli --skip-command-sweep --coverage-only --capacity-check --capacity-records 1000 --skip-kingdee`；5000档替换最后的数量。数量仅接受0/1000/5000，合成标识和目录边界必须成立；没有正式地址参数。初始化只在合成库增加新ID，读取负载期间写入0。69组业务适配检查加该项为70组，并非70个全新负载场景。
