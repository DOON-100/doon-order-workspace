## 目标和范围

按 `app/business-process-panel.tsx` 的 13 个订单阶段组织工作，覆盖 `lib/department-workspace-navigation.ts` 的全部 11 个栏目，包括工作总览、业务、客服单证、工程、PMC、采购外协、仓储物流、生产、品质、财务及系统管理。最终目标是：员工登录后，能通过 CLI 完成其权限内、中台实际支持的表单与数据操作，包括新增、查询、修改，以及业务规则允许的删除、撤销、停用或归档；权限、客户/订单/业务组范围和字段限制与服务器一致。只读报表、历史、审计和不允许删除的数据保留原有语义，不为凑齐 CRUD 而增加物理删除。

按第一性原理，W0 只需准备一条可复用的安全调用链：员工会话、限定接口、结构化输入、服务器权限、结果及错误处理、回读和隔离测试，并登记栏目和后续批次。全站逐页面、逐表单、逐字段、逐动作和逐角色的详细矩阵，随 W1–W10 各业务批次逐项核对和实现，不作为开始第一批业务开发的前置条件。每批仍需补齐该批查询、字段、权限、接口和验收；只读、撤销/归档和无法安全支持的动作如实标注，不推断 CRUD。不同页面共用同一底层记录时复用能力。系统运维 Shell、直接访问数据库、服务器部署不属于数据中台表单操作。

## 统一命令设计（草案）

以下为计划中的示例，实际命令名称和参数以逐批核对后公布的帮助文档为准，并沿用现有查询命名，避免破坏已有脚本。

```text
doon <业务组> <资源> list|show|history
doon <业务组> <资源> schema --type <表单类型>
doon <业务组> <资源> create --type <表单类型> --input <文件>
doon <业务组> <资源> update <编号> --input <文件> --version <版本>
doon <业务组> <资源> <业务动作> <编号> ...
```

- 命令框架、参数解析、字段说明、输入校验、输出格式、鉴权、错误处理和结果回读统一实现。同一数据模型且业务语义一致的表单使用同一命令，通过 `--type` 区分；不同类型仍使用各自字段校验，不因为参数相似就合并实际不同的业务动作。具体是否存在版本号、是否支持删除，以服务器契约为准。
- 如流程作业计划以一套命令配合 `--type rfq|sample|iqc|...` 复用 `process-save`；具体种类及字段以服务器允许列表和各自校验规则为准。项目财务登记可评估复用 `project-finance-entry-save` 的 `entryType`，收款核实、冲销、分配、退款等继续使用独立动作。模板、导入、附件上传及导出按各自协议处理。
- `schema` 计划给出允许字段、必填项及类型，输入文件须显式指定、限制大小并校验；密码和凭据不作为命令行参数、不进入帮助、输出或日志。员工仍用自己的账号登录；Codex、WorkBuddy 按命令说明调用 CLI，不要求 MCP，也不开放任意 HTTP 路由、Shell 或数据库。
- 输入校验只是便利，服务端必须独立校验身份、权限、范围、字段、状态和必要的版本；`--type`、本地帮助或客户端过滤不能扩大权限。错误应清楚区分无权限、版本冲突、内容不合法和结果未知。
- 用户于 2026-10-27 明确：CLI 不实现操作确认、重复确认、对话确认读取或传递逻辑。员工与 Codex / WorkBuddy 的交互由各自工具负责；CLI 按员工请求调用对应业务接口，不为 CLI 新增确认流程或确认参数。
- 中台既有的业务状态、审批、账号权限及第一阶段规则继续生效。CLI 对服务器要求的条件和拒绝结果如实返回，不伪造审批或把对话/操作日志当作服务端审批凭证；如果某类模型提案需要既有审批而服务器无法满足，列为未支持并暂缓。业务表单原有的确认、提交、审批等是业务操作，不新增 CLI 侧二次确认。
- 对已有预览能力先核实其是否只读或会登记提案，再如实说明；不得把实际会写入或外发的入口称作试运行。
- 写入前核对关联与版本，适用时使用服务端支持的幂等标识；同标识不同内容须拒绝。缺失安全能力时先补服务器接口或暂缓，不用客户端模拟服务器保证。执行后按权限回读和记录结果；超时或连接中断导致结果不明时先查询原操作，不能盲目重试。保留原业务记录、历史和附件原件。

## 员工分发与连接（W0 设计）

- 先支持 Windows x64：管理员从经过验证的构建取得带提交号、版本及文件摘要的安装包，通过公司的可信下载入口分发；员工安装到各自 Windows 用户目录，配置公司 HTTPS 地址，再以本人账号登录。包和公开仓库不包含服务器私有地址、密码、会话或业务数据。构建 artifact 有保留期限，只是当前测试来源，正式下载入口和负责发布的人员尚未确定。
- 更新时先核对版本、提交号、平台及摘要，再安装新版本；保留旧程序供回退，不覆盖员工业务数据、服务器数据库或员工会话。强制升级、自动更新和其他操作系统客户端均需另行实现和验收；当前不声称已支持。
- CLI 只连接同一个经过配置的 HTTPS 地址，并使用员工个人会话调用服务器；无通用代理、数据库或任意 Shell 入口。现有客户端单次调用串行请求、不后台轮询；这不是服务器总并发或最大接入人数承诺。服务器的连接、会话和代理限制、并发容量及瓶颈需要 W11 用独立环境实测，正式环境容量上线前另行核对。
- Codex / WorkBuddy 调用员工本地 CLI 和命令说明，不需 MCP。实际员工安装、权限差异、客户端升级及两种工具的真实操作仍需验收；中台已有业务授权和审批不因分发 CLI 而改变。
