# 2026-10-22 Agent DeepSeek 400 排查与修复

## 已确认原因

服务器日志在北京时间 11:14:18、11:14:35、11:14:46 记录了三次 DeepSeek HTTP 400。运行中的 Agent 镜像为 `20261021-auth-resilience`，模型请求为 `deepseek-flash`、thinking disabled、流式响应。原错误处理隐藏了厂商原始消息，因此单看通用“格式错误”提示不能确定根因。

在同一服务器使用合成输入做受控对照：不携带工具的请求返回 200；携带当前部门工具定义的请求返回 400，厂商明确指出 `departmentSales` 的参数 schema 顶层缺少 `type: object`。十个部门工具共用顶层 `z.discriminatedUnion`，转换后只有联合分支，不满足该接口的顶层对象要求。这次复现发生在工具执行前，与共享路径是否可访问无关。

## 修复边界

给模型的参数定义改为严格的顶层对象，提供 operation 枚举及 action、arguments 字段说明；固定执行器继续使用原 discriminated union 对各操作逐项校验。list 禁止夹带 action/arguments，inspect/query/prepare 的必填字段、权限、范围、来源和确认约束不变。未增加文件访问、业务写入、外发、模型切换或自动重试能力。

回归通过实际 Mastra 与 DeepSeek SDK 捕获请求，覆盖流式和非流式两步工具回合，并检查所有十个部门工具和三个工作流工具的顶层对象契约；缺字段、额外字段在业务读取前被拒绝。

修复模块在服务器独立诊断进程中加载，不覆盖运行文件、不替换容器。真实模型以非流式、流式分别验证合成目录查询及共享报价任务，两轮共六个请求全部返回 200，部门目录工具调用成功，生产业务读取为零，没有保存会话或修改生产数据库。这只证明候选修复与当前模型兼容，不代表修复已经部署。

## 共享文件生成报价任务的验证结论

通过当前工具目录及等价合成指令核对，当前 Agent **不能完成“到 Windows 共享目录寻找指定文件并生成报价单”的完整任务**：

- 没有 SMB／共享目录浏览、搜索及读取工具；发送路径并不会赋予服务器或模型文件访问能力。
- 可以经受权只读接口查询系统内客户报价、已完成报价和报价模板元数据，但这些能力不等于能读取共享盘原文件。
- 报价模板导出、已完成报价导出和成品文件获取接口尚未接入 Agent 执行器，目录状态为 `not-executable`。
- 合成任务中真实模型明确说明无法读取共享目录，未声称找到文件或生成报价成品。

后续若要接通该任务，需要单独设计受限目录的只读文件桥、来源及版本核验、固定报价生成程序与人工确认流程，并用下载产物及回读结果验收。不能把本次 HTTP 400 修复当作报价链路已上线。
