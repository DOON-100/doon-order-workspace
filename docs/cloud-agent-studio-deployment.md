# 云端 Agent Studio 部署验收

日期：2026-10-17。Agent 基线为 `codex/mastra-local-validation` 的 `f8044fb` 加本次容器与网关实现；最终源码提交由 Git 历史及服务器私有发布清单关联。

## 发布方式

数据中台继续原生运行，后续从最新且通过适用检查的 `origin/main` 更新。Agent 独立使用版本化 Docker 镜像发布和回退，两者分别验收；本次没有顺带升级中台代码。后续中台更新需核对 `/api/auth/session` 返回结构以及公司图标选择器的兼容性。

本次镜像版本为 `20261017-studio1`，镜像 ID 为 `sha256:4be95a00bb7a691384bd1a7b7dac31221d408e2b49b2f97ab4f50f2e03d4e354`。构建只包含运行文件，不包含业务数据库、附件、测试脚本或凭据。凭据通过受保护的宿主机文件挂载，不写入镜像和公开仓库。实际主机地址、密钥和运行配置只保存在私有部署环境。

## 与中台的联系

- **入口已部署。** 原 HTTPS 入口将 `/studio/*` 转发给仅发布到宿主机 loopback 的 Agent 容器。中台 HTML 注入入口脚本，登录后的管理员和程序员可从原公司图标打开 Agent Studio；图案、尺寸和业务页面布局保持原样。
- **复用登录，逐次鉴权。** 容器通过带证书校验的 HTTPS 调用中台 `/api/auth/session`，检查现有会话、当前角色与首次改密状态。没有另建 Studio 账号，不读取密码，不把会话交给模型。匿名 Studio 首页跳回登录，受保护资源和 API 返回 401。
- **数据独立。** 中台继续使用原数据库及附件；Agent 使用独立 PostgreSQL 记忆库和观测库，不挂载中台数据库或附件目录。
- **业务接口尚未接入。** 当前四个 Agent 只使用固定合成场景，不读取正式订单，不写业务记录，不发企业微信。登录链路已接通，不代表采购、PMC、客服、人工审批与消息回执业务链路已验收。

## 验收边界与后续

没有读取现有员工密码、复用现有员工 Cookie 或创建生产测试账号，因此尚未使用真实用户完成浏览器登录后的点击与云端 Metrics 图表人工验收。入口和鉴权的正向行为由合成测试覆盖；真实模型、数据库落盘和重建持久性已在服务器内部验证。

当前 Studio 为授权技术人员共享的合成验证环境，尚未实现业务用户/任务级 memory 隔离。轨迹七天清理、业务数据按阈值清理、人员信息长期保存及审批/企微按钮交互属于后续独立功能，本次未启用自动删除策略。

后续首先按最小权限设计中台只读业务 API，逐个工具验收，再接入有真实身份、载荷版本、幂等和审计的人工审批接口；遵守第一阶段固定程序优先、LLM 辅助、人工确认原则。

## 运维约束

按新版本镜像重建 Agent 容器；保留 PostgreSQL 命名卷、独立数据库和原中台持久化目录。每次更新备份后记录源码提交、镜像 ID 与验收摘要。回退只切换代码/镜像和必要的代理配置，不以旧备份覆盖现库，不使用 `down -v`。

长期改用 CI 构建和私有镜像仓库分发，服务器只保留运行程序、必要配置、密钥、数据库、附件、备份和镜像；服务器临时构建源文件在归档与验收后清理。具体配置模板见 [Agent 容器说明](../experiments/agent-server/README.md)。

## 默认 HTTPS 端口启动修复

同日浏览器验收发现：官方 Studio 在 `MASTRA_SERVER_PORT` 为空且未开启 URL 自动识别时，会将连接端口回退到 4111，导致公开 HTTPS 页面停在手工连接配置页。仅检查页面 HTTP 200 和 Agent API 不足以证明浏览器已完成初始化。

修复版镜像 `20261017-studio2` 设置 `MASTRA_AUTO_DETECT_URL=true`，使用浏览器当前 Origin，API 前缀保持 `/studio/api`，不需要用户手填地址或请求头。镜像 ID 为 `sha256:abcd3860fccbf0e85c2fb0eee6dc4f32baa417e447d10cc5f3e2f31d2022c369`；原镜像保留用于代码回退。

新增回归测试直接执行当前安装的官方 Studio bundle 中的启动函数，核对 HTTPS/HTTP 默认端口、本地端口及自定义 HTTPS 端口均选择当前 Origin，并验证 `/auth/capabilities` 握手返回官方需要的结构。云端运行相同启动核验，握手成功且 Agent 列表返回 4 个 Agent。本次不修改中台业务代码、nginx、账号或数据结构。

独立的本地合成浏览器环境已自动进入四个 Agent 的列表页，公司标识及侧栏正常显示，没有出现连接配置表单；该环境不使用生产账号或真实模型密钥。修复后相关测试共 11 项通过，并通过 TypeScript 检查。真实云端用户刷新后的最终显示仍由其现有登录会话验收，不以本地截图替代。

## 非空 Traces 查询兼容性修复

同日 Traces 页面报告 `invalid_union`，拒绝 `outputPreview` / `errorPreview`。云端复现确认错误来自服务端响应校验：`@mastra/server` 1.78.0 和 PostgreSQL 适配器已返回两个预览字段，但锁定的 `@mastra/core` 1.77.0 响应 schema 尚不接受它们；数据库实际已有轨迹，查询接口返回 500。

将 `@mastra/core` 精确锁定到 1.78.0，与服务端对齐；依赖锁文件同时更新其 `schema-compat` 至 1.3.15，其他组件保持原版本。保留官方严格校验、原始输出预览和错误预览，不删除数据库字段或轨迹，不在网关吞掉数据。修复版镜像为 `20261017-studio3`，镜像 ID 为 `sha256:a0414967859972280ea16660de5cdf0b163bbf6e21dc1deb5a18884a1ec87c2a`。

新增合成响应契约测试，经实际 Hono 路由校验非空列表、游标/页码两种分页、输出/错误预览及未知字段拒绝；相关 12 项测试、TypeScript 和 diff 检查通过。云端使用真实 PostgreSQL 数据验证查询返回 200、页码分页、增量查询、轨迹详情和根 span 详情均正常。

发布前完成一致性备份，并对原有 span、metric、thread 和 message 逐行记录内容哈希。更新后全部原记录哈希仍存在，数量未变；原中台业务记录、账号和附件核对一致，中台进程未重启。该验证为服务器内部接口验收，真实浏览器使用者可刷新 Traces 页面完成现有会话下的显示验收。
