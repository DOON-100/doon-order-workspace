# 业务记录的附件与沟通

业务栏目和明细行提供“上传附件”“记录沟通”“查看记录”。打开入口后，先确认具体业务记录和栏目，再保存文字、附件或两者。每次保存独立保留记录人、时间、原文件及 SHA-256，不修改原业务数据，也不推进审核、收款或生产状态。

项目资料目录的所有栏目均可保存独立跟进记录。`00_项目资料.md` 的正文版本管理、`99_旧版本` 的归档规则及正式附件目录保持原样。明细行绑定具体记录；栏目入口绑定页面标示的项目页签。其他业务入口提供当前授权记录的搜索和选择。

## 存储与访问

- 新增独立记录类型 `business_followup`、`business_followup_attachment`、`business_followup_request`，不迁移或改写旧记录。
- 目标目录复用业务领域接口和业务组过滤；仅接收明确支持的模块、集合、记录及栏目。客户端提供的名称或客户编号不授予权限。
- 同一业务记录的不同页面入口使用同一规范目标。每次读取、保存、重放和下载都重新检查当前权限和业务归属；归属变动不会将旧记录透露给新的客户。
- 工程报价、销售报价、付款目录沿用专门权限。新记录内容不进入通用订单审计接口。
- 下载检查文件长度和 SHA-256，强制作为附件返回，不在同源页面执行上传内容。
- 每次最多 10 个非空文件，每件 20 MiB。服务端整个 multipart 请求限 50 MiB，界面文件合计限 49 MiB，为表单开销留出空间。

## 重试与草稿

提交生成 UUID，固定目标、业务组、文字、文件顺序及内容哈希。重复提交原请求只返回原记录；同一 UUID 的异内容提交被拒绝。网络中断或结果不完整时保留原请求供重试。栏目入口打开统一对话框，切换宿主区块不会丢掉草稿；页面导航与业务组切换沿用未保存内容保护。

新增业务入口应通过 `BusinessFollowupProvider` / `BusinessFollowupSlot` 接入，并在服务端目标目录中提供既有领域授权。不可仅按客户端传入的实体 ID、客户 ID 或聚合记录的 sourceId 推断访问权限。

## 验证与发布

使用合成数据运行 `node tests/run.mjs`、TypeScript 检查及隔离目录中的 standalone 构建和运行时测试。功能开发和 Git 推送不更新正式 8787 服务；正式发布仍按 `AGENTS.md` 的备份、原件核验及代码回退规则执行。
