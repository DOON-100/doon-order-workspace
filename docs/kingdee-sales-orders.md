# 中英文订单转金蝶销售订单

入口为“客服与单证 → 金蝶销售订单”，也位于生产单页签的“中英生产单”后。中英内部订单中的已导入销售原单可直接定位到本入口。

## 操作流程

1. 选择已导入的中英文销售原单，或下载标准中英文订单上传模板、填写并上传。上传先展示解析预览，确认后保全原文件并登记独立销售原单。
2. 点击“生成金蝶销售订单”，按来源明细建立独立草稿。补齐单据日期、客户、业务员、币别、汇率、业务类型、单位、价格、税率及交期。
3. 成品编码按“类别－客户编码－图纸编号－客户型号－板料/电镀颜色编码－色号”生成。客户原 SKU 不能替代成品编码；缺项不能凭空补齐。不同成品类别须分单，样办数量不能直接加到订单数量中。
4. 保存草稿并检查订单，查看缺项、原单调整提醒与金额。下载的金蝶订单使用已上传的官方销售订单模板，保留模板字典和字段，不增加审核辅助列。
5. 客服逐项核对后勾选确认、点击“客服确认无误”。只有满足连接条件、权限、版本和业务字段映射要求，才可点击“确认上传到金蝶”。来源、模板或草稿变动会使确认失效。
6. 提交结果必须通过金蝶回读核验。超时、回执异常或字段不一致显示“结果待核查”，不能再次新增同一订单。使用“核查上传结果”检查原动作。

## 直接上传的当前限制

官方 Excel 模板实体为 `销售订单 # sal_bill_order`，其中 `transtype` 是必填字段，取值包括“现销”“赊销”。已核对的星辰销售订单保存和详情 API 仅说明 `biz_mode` 为“普通/直运”，没有证据证明它等价于模板业务类型；不能将“现销/赊销”猜映射成“普通/直运”。

核对依据：[金蝶销售订单保存](https://open.jdy.com/#/files/api/detail?index=3&categrayId=3cc8ee9a663e11eda5c84b5d383a2b93&id=9e6856b0712511eda0b38d6dfb52f735)、[金蝶销售订单详情](https://open.jdy.com/#/files/api/detail?index=3&categrayId=3cc8ee9a663e11eda5c84b5d383a2b93&id=9e6e7132712511eda0b3b9a1d236ec55)，以及已核定的 15 列销售订单模板和 2025-07-08 成品编码规则。

因此，当前版本明确阻断直接 API 上传，保留完整的模板订单生成、客服核对和确认流程。须取得服务商的字段映射说明或经核定的账套接口合同，再补充该映射及回读验收，才能开放直接上传。程序不会将文件下载或模板导出显示为“已上传金蝶”。

销售写权限单独由 `DOON_KINGDEE_SALES_WRITE_ENABLED` 控制，默认关闭；采购只读开关不授予销售写权限。仅打开销售写开关仍不能绕过上述业务类型映射阻断。正式配置、上线及真实 ERP 业务提交属于独立操作，本次代码开发和合成测试不执行这些动作。

## 数据与权限

原单、草稿、客服确认、提交尝试和回执独立记录，既有生产订单、PMC数量、采购记录与附件不被转换或覆盖。原单明细数和来源行标识在每次保存及确认时重新核对。业务组筛选只缩小授权范围。

仅有效内部管理员或客户明确责任人员可读；准备和客服确认分别检查权限。客服确认绑定当前成员、草稿版本、来源、模板、规则和有效期。商业资料不会通过通用审计流向无权读取的员工公开。

## 验证

使用合成订单、临时 SQLite 数据库、模拟金蝶响应和独立测试端口。检查权限、缺项、编码规则、来源及模板版本变化、模板结构、重复提交、未知结果、回读差异和原业务记录完整性。构建输出仅写到 `test-output/`，不得覆盖正式 `lan-dist/` 或启动/重启 8787。

`tests/kingdee-sales-cases.mjs` 另在专用测试构建中替换协议就绪检查，用完全模拟的响应验证未来直传执行器的幂等与回读行为；生产源码的映射阻断始终保留。该测试不证明现有金蝶账套已完成真实写入联调。
