# 实收总表与收款原件

业务/客服登记收款审核依据，财务查看、下载资料用于核对，最终确认人固定为唯一在职成员“朱了青”。历史审核说明只表示用户提供的既有审核事实；未提供的历史审核人和时间不补造。登记操作者及登记时间单独留痕。姓名不唯一或账号停用时阻断最终确认，不扩大其他账号的确认权限。

原件使用 `payment_proof_inbox`，总表使用独立 `receipt_master_entry`。原有凭证、应收、余额与核销均保持不变。新上传图片/PDF与总表来源在同一次提交中登记；历史原件按真实ID幂等补登记，业务审核依据须由有写入权限管理员明确提供。归档本身不代表新增记录已完成业务审核或最终确认。

每份凭证可以拆录多笔收款；同笔多图指向主记录，核对资料和退款资料不计实收。金额、币种、日期及付款人缺失时保留空白并阻止普通收款最终确认。汇总只包含已最终确认、收款类别、非重复来源的分笔；整数分计算、币种分开，不换算。最终确认绑定当前版本及来源摘要，确认后不可覆盖。

## 功能与验收矩阵

| 功能 | 实现 | 验证 | 状态 |
|---|---|---|---|
| 新图片/PDF原件和总表来源原子登记 | 鉴权上传、SHA256去重、私有原件；PDF以附件下载 | `tests/payment-proof-inbox.mjs` 原件字节回读与上传记录断言 | 合成测试通过 |
| 历史收款审核说明 | 指定原件ID、审核依据、录入人及时间；重复提交不重复登记 | 同上，幂等和旧原件不变 | 合成测试通过 |
| 最终确认 | 朱了青本人、在职唯一账号、版本/来源校验、确认后不可覆盖 | 同上，其他管理员被拒、缺字段被拒、旧版本被拒 | 合成测试通过 |
| 财务取资料核对 | 总表和原件只读下载，无总表登记、编辑或代确认权限 | 同上，财务写入被拒及原件回读 | 合成测试通过 |
| 多笔、多币种与重复材料 | 分笔录入、主凭证关联、类型区分、原币种确认后汇总 | 同上，多币种分别汇总；原应收不变 | 合成测试通过 |
| 全字段组合筛选 | 共用 `ExcelTable` / `useExcelColumnFilters`，完整授权记录筛选，不先分页 | 共用筛选组件既有回归与页面验收 | 网页筛选；不是工作簿计算引擎 |

正式运行效果须另行发布及页面验收。每天群历史扫描由现有Codex自动化任务执行，非本模块中的服务器定时器；电脑、企业微信登录及原件可下载性仍是执行条件。未读取完整历史或有缺失原件时不推进全量完成检查点。
