# 原生服务部署工具

本工具校验 CI 部署包，经 Workbench 上传后切换原生服务。代码提交、导入本模块和运行本地测试都不会执行部署。

## 本地配置

复制 `config.example.json` 为 `local-config.json`，填写实例、区域、Workbench 路径、服务器版本目录、systemd 配置目录、Node 路径、环境文件引用、服务名和数据目录。该文件已被 Git 忽略，禁止提交真实服务器配置、密码或密钥。未提供有效配置时拒绝部署；示例中的空实例不能直接使用。

`WORKBENCH` 可覆盖本机工具路径；`DOON_DEPLOY_HEALTH_HOST` 可覆盖健康检查 Host。鉴权由已配置的 Workbench 提供，不在本工具中保存凭据。

## 使用

依赖本机 Node.js、Python 3 和 Workbench，服务器需要 Python 3、systemd 及原生运行环境。

双击 `部署.bat`，或执行：

```powershell
node deploy-tool/deploy.mjs "C:\path\to\release.zip"
```

工具校验 `release.json`、目标平台、提交编号、tar 文件名和 SHA-256。确认目标后才上传和切换；`--yes` 只适用于调用者已明确授权的部署，不表示代码同步后可自动部署。

## 数据与版本保护

- 每次部署生成独立版本目录和上传路径，即使提交相同也不覆盖旧目录。已存在的目标目录会被拒绝，旧程序及回退点保留。
- SQLite 使用在线备份接口，包含已提交的 WAL 内容；备份文件独占创建，完成后检查完整性并输出 SHA-256。失败时停止切换，不复制正在运行的数据库主文件。
- 新增独立服务配置并校验实际生效目录，保留旧配置；切换后核对进程工作目录、启动入口及发布清单的提交编号。
- `/health` 和 `/` 必须返回 200，健康响应必须为 `ok=true`。403、500、跳转、错误进程或版本不能报告部署成功。验证失败只报告失败，不自动恢复旧数据库。

部署失败可明确选择撤销本次配置并重启；尚未确认写入新配置时，不按提交编号猜测回退路径。手动回退须使用本次输出的准确配置路径，不删除旧版本目录，不覆盖业务数据。保留代码回退点不等于已验证所有旧程序与当前数据兼容。

## 本地验证

在仓库根目录执行：

```powershell
node --test deploy-tool/safety.test.mjs
```

测试只使用临时目录、合成数据库和本机随机端口，覆盖配置校验、WAL 备份、重复目录保护、配置排序、HTTP 错误及运行版本校验，不连接或部署真实服务器。
