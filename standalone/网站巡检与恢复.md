1. 工作目录为 `D:/DOON/doon-factory/订单协作中台/web`。核对实际网卡地址和 `lan-data/server-status.json`，状态文件不代表进程仍在运行。

4. 使用 `C:/Program Files/nodejs/node.exe scripts/check-lan-login.mjs` 只读核对账号启用状态、有效登录失败记录和数据库。不要因历史数量变化就恢复旧数据；员工日常操作会正常改变记录。
5. 查看 `lan-data/service-status.json`、`service-events.jsonl`、`server-error.log`，以及 Windows 任务 `DOON-Order-Workspace` 的运行状态。`monitoring-existing` 表示正监测已有健康进程，`running` 表示守护自己启动的进程正常，均为正常状态。

## 自动恢复

- 服务健康时不重启。服务停止且没有人工维护或明确停机标记时，运行 `standalone/启动订单中台.ps1`，之后重新验证本机、内网、登录接口和数据库。
- 如任务被有意禁用（例如部署或维修），尊重停机状态，报告所需操作；不要与人工维护竞争。
- 如服务进程仍存在但接口持续错误，进行两次短间隔复核，保留脱敏错误；确认 PID、程序名称和命令均对应当前项目后，可使用本项目停止和启动脚本恢复一次。不要杀死无关进程、连续循环重启或按陈旧 PID 结束程序。
- 启动脚本会恢复已暂停的守护；停止脚本会先禁用守护任务，避免维护时重新启动。
- 不恢复旧备份覆盖现有数据，不删库、不重置密码、不改变成员权限、不关闭防火墙、不扩大可访问网段、不调整电源设置。需要这些操作或工具实际权限不足时说明具体原因。
- 运行记录保存于 `lan-data/site-monitor.json`。已有异常没有变化不重复提醒；新故障、恢复成功、故障变化或需要用户操作时通知当前任务。

## 运行条件

Windows 任务使用 Hello 当前用户的普通权限，不保存密码。用户登录后自动运行；服务进程退出后约 5 秒尝试恢复，守护任务退出后每分钟尝试重新启动。主机关机、睡眠、断网或该用户注销期间网站不可用。小时巡检由 Codex 调度，需要本机 Codex 执行环境在线。未安装公网服务，也不发送群消息。
