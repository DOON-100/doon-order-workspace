# 客户历史报价模板导入说明

使用产品SKU、历史价格、来源文件、填写说明四张表的通用模板。第5行是中文标签，第6行是稳定字段名，从第7行填写数据。保留工作表名和第6行字段顺序。导入前删除DEMO合成示例，用真实客户代码填写三个数据表。

产品记录ID、价格记录ID和来源文件ID在本客户范围内唯一。价格表的productId须对应产品表，sourceFileId须对应来源表。每个有依据的SKU建一条产品记录；款级资料不推定为所有颜色的SKU价。打样、下单、生产和交货状态分别记录。

一条历史价格保存一个版本和一个数量条件。原币单价、独立费用、计价单位分别填写，价格缺失留空，明确免收才填0。INVOICE与匹配产品的报价冲突时优先INVOICE，报价历史仍保留；不同配置、币种或单位不能混配。发送状态指对客报价是否发送，审核通过或发票存在不能替代发送凭证。

同一SKU的RX与Solar等配置分别建价格行，在configuration填写原文配置，lensVariant填写本条价格对应的镜片原文；主产品镜片不能替代历史价格的镜片条件。invoiceKind可填proforma（形式发票）、commercial（商业发票）、unknown，非发票可空。发票性质不代表交货状态。

日期填真实日期或YYYY-MM-DD，金额和数量填数值，避免将币种放入数字单元格。核对后的原值用于导入，不使用公式。缺币种、日期或其他事实的历史资料标记needs_review；不为填满表格补造条款或日期。

转换器在本机生成JSON，不修改数据库。先选择单个客户代码，其他客户行不进入该客户的导入结果。以下命令在中台web目录运行：

```powershell
node standalone/customer-price-template-to-json.mjs --input "已填写模板.xlsx" --output "私有客户报价.json" --customer-code "实际客户代码" --customer-name "客户名称"
```

如需随导入保存原文件，来源文件表填相对文件路径，再指定原件目录：

```powershell
node standalone/customer-price-template-to-json.mjs --input "已填写模板.xlsx" --output "私有客户报价.json" --customer-code "实际客户代码" --source-root "原件目录"
```

转换器检查原件目录边界和文件哈希。只有路径在指定目录内且指纹一致的文件才能关联；不执行单元格公式。没有原件目录时只生成来源索引，附件导入阶段仍需补原文件和指纹。

生成JSON后，使用客户价格档案的导入工具先进行dry-run，核对选定客户ID、来源文件、记录数量和待核对问题，再应用。数据库导入需要明确客户ID及已有版本条件，不按客户代码前缀授予访问权限。

JSON、Excel总表、原件和数据库属于私有业务资料，不提交到公开源码仓库。
