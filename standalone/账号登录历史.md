# 账号登录历史

管理员在“成员与权限 → 账号登录历史”查看、刷新或按登录账号筛选记录，也可加载更早记录。管理员接口为 `GET /api/auth/history?username=employee01&limit=50`，返回 `nextBefore` 时，下一页传入 `before=nextBefore`。普通员工及供应商不能读取该接口。

从此功能上线后，员工、供应商和内网入口的认证处理器追加独立的 `auth_event` 记录，包含登录成功、登录失败（含认证限流）和已认证账号的主动退出，以及账号、UTC 时间、可信客户端 IP、入口和结果原因。页面统一显示北京时间。登录失败中的账号只是尝试登录的目标，不证明账号本人操作；不存在的账号也可在“全部账号”查看。登录成功可能仍要求首次修改密码。

历史不保存密码、密码摘要、Cookie、会话令牌或令牌摘要。成功登录的会话与历史记录在同一事务提交，保存失败不签发会话。代理入口仅使用既有网关验证后的客户端地址；内网入口不信任客户端自行填写的转发头。

不会追补上线前的登录。浏览器关闭、会话超时、重置密码导致会话失效不属于主动退出；密码重置仍保留原有账号管理审计。跨站、无效代理等在认证处理器之前被拒绝的请求，以及外层 HTTP 请求限流，不属于这里的登录认证历史。只读验收模式沿用只读规则，不向副本写入登录历史。

## 通过阿里云 CLI 监看

本机已配置 Workbench CLI 时，PowerShell 可以运行下列单行命令。参数使用实际 ECS、地域和数据目录；示例值不对应生产环境。

```powershell
powershell.exe -NoProfile -File "standalone\watch-account-history.ps1" -InstanceId "i-example" -Region "cn-example" -DataDirectory "/path/to/data" -Username "employee01"
```

脚本在指定 ECS 上以 SQLite `mode=ro` 查询。范围包括该账号执行的业务审计、以其成员／账号编号为目标的管理变更、登录事件、模块独立版本与事件、记录内嵌的审核和协作历史，以及有可辨认操作人的导入、导出和附件凭据。技术幂等请求与 mutation 记录不作为业务历史展示。

首次完整显示已有历史，没有 200 条截断，`-Once` 同样读取全部；随后每 5 秒重新比对历史事件的稳定编号和 SHA-256，只显示新增或变化的凭据。因此，向原任务追加历史（没有新增父记录 rowid）也能被发现。Ctrl+C 停止，`-IntervalSeconds` 可调整间隔。

输出包含北京时间、操作账号、操作类型、目标编号、来源记录类型、关联关系、IP（有记录时）、版本、变化字段名称和内容摘要哈希；不输出原业务内容、邮件正文、原始快照、密码或会话凭据。同一次操作可能同时保留审计、版本和审核凭据，按来源分别展示，不应把行数当作操作次数。旧记录只有姓名时，仅在姓名能唯一对应一个成员的情况下匹配，并标注 `identity=unique-name`；明确成员 ID 优先，同名或不明确的记录不冒认本人。未保存过的操作不能还原，缺失的 IP 或时间保持空白。

node standalone/test-auth-history.mjs

node tests/run.mjs
