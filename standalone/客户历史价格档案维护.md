# 客户历史价格档案维护

历史价格使用现有 SQLite `records` 和不可变附件存储，新增 `customer_price_archive` 导入批次。每批保存产品 / SKU、原币历史价格、资料性质、数量条件、来源工作表 / 单元格 / 页码。现有报价、生产订单、客户责任及账号不会由价格导入工具覆盖。

## 生成与核对

输入为私有 JSON：`schemaVersion: 1`，包含 `customer {code,name}`、`files`、`products`、`prices`、`issues`，可附 `excluded`。格式参考本仓库合成测试和 `customer-price-template-to-json.mjs`，不要把真实数据或源件放入公开仓库。文件路径只用于本机处理，入库会去掉绝对 `path`，保留相对来源位置。

价格 `documentType` 使用 `invoice`、`quote`、`order`、`internal`、`charge`。`invoiceKind` 可区分 proforma 等子类型；INVOICE 是用户指定的查询依据，不表示已发货或已发送报价。`configuration` 区分 RX、Solar 等配置，`lensVariant` 保存原单据本条价格的镜片条件。页面与导出明确显示“本条价格镜片”，不以产品主标签替代该条件。核对状态 `verified / needs_review` 与发送事实 `unknown / sent` 分开，空价为 null，不能填 0 或自动推算 SKU。

同产品以原币、单位、款级 / SKU 范围、配置、本条价格镜片、数量条件、条款并列依据；同条件 INVOICE 优先，最新待核对 INVOICE 不回退旧已核对价。不同镜片不会混为同一条件，也不据此创造新 SKU。旧报价仍在历史中；不同源版本或同条件冲突须复核。内部核价不作为销售价依据。

## 受控导入

先构建到单独测试目录并通过业务、TypeScript、内网及浏览器检查。导入默认 dry-run；明确客户 ID，不从目录名、客户编码前缀或姓名猜权限。

```powershell
node standalone/import-customer-price-archive.mjs --build-dir test-output/quote-review-build --dataset <私有dataset.json> --customer-id <已确认客户ID> --dry-run
node standalone/import-customer-price-archive.mjs --build-dir test-output/quote-review-build --dataset <同份私有dataset.json> --customer-id <已确认客户ID> --source-root <不可变原件快照目录> --apply
```

`DOON_DATA_DIR` 明确指定目标数据目录，未设置时为 `lan-data`。生产应用前先按现有流程在线备份数据库及 files，并保留可恢复副本。首次导入只新增批次与审计；客户 ID + 内容摘要决定批次 ID，同批重传幂等。指定 `--source-root` 时，对所有 included 来源校验真实路径、大小和 SHA256，再逐个归档；单原件上限 64 MB。未指定则只迁入来源元数据，报告 `metadataOnly: true`，不能据此宣称原件已归档。

遇到失败不会自动回滚 / 覆盖生产数据库；检查已保留批次与已归档文件后重试同一批。原件以新不可变存储键写入，失败不删除任何旧文件；同客户同 hash 原件复用已有指针。

## 独立权限与身份绑定

所有档案查询、统计、历史、Excel 和原件都经过专属报价 API。普通成员须在报价名单内，且匹配本人客户。客户页报价入口使用后端返回的授权客户 ID；报价数据不加入通用客户清单。

授权策略可包含 `memberIds`、`aliasesByMember`、`administratorMemberIds`、`internalMemberIds`、`customerMemberIds`。客户档案中显式 `quoteMemberIds` 优先，空名单明确撤销普通成员的该客户报价权限；以后责任调整优先使用客户责任清单界面。策略 `customerMemberIds` 仅兼容尚未配置新版客户报价成员名单的客户；该稳定客户 ID -> member ID 映射存在时不回退姓名 / 别名。两处都未指定名单的旧客户按完整确认姓名 / 别名兼容，不使用部分姓名或 PMC / 全订单权限扩权。客户名单不会绕过账号级报价资格或内部字段权限。

独立报价管理员可查全部客户、内部资料和原件；普通账号默认只看已核对销售价摘录。原件可能含成本和多客户，始终仅报价管理员下载。旧报价内部字段及审计同时过滤；普通客户端空白内部字段被忽略并保留原成本，非空越权修改被拒绝。

配置必须使用已核对的本人独立账号；不把通用管理员账号当作某个人，也不读取密码或会话。

```powershell
node standalone/update-customer-quote-access.mjs --build-dir test-output/quote-review-build --config <私有已审核权限JSON> --dry-run
node standalone/update-customer-quote-access.mjs --build-dir test-output/quote-review-build --config <同份权限JSON> --apply
```

配置提供完整策略字段、`expectedPolicySha256`（现有策略的 canonical JSON SHA256，未有策略时 null），以及所有被授予权限人员的 `expectedMembers [{id,name,username,accountId}]`。工具验证姓名、登录名、账号 ID 和成员身份一致，摘要不符拒绝覆盖。仅系统管理员可改变授权策略；授予报价管理员不会把其员工角色自动改成全系统管理员。API 对省略的扩展权限字段保留旧值，明确空数组 / 对象才会清除。

## 验证

默认查询和 Excel 为 `view=sku`：每客户每个 `frame` 成品 SKU 一行，只从 `scope=sku` 的最新日期 INVOICE 选择，不按数量、规格或镜片条件拆行，不用报价 / 订单 / 款级价补填。没有 SKU 发票留空；配件、费用和无 SKU 资料不进入主表。`view=history` 保留完整原历史、条件和来源，并沿用相同权限。单客户默认 Excel 为 SKU、款号款名、框色、币种、发票单价、发票日期、发票号、核对状态八列，全部客户导出增加客户两列。

最新日期发票只有一个币种 / 单位 / 单价时直接保留，与 RX / Solar 偏好无关。出现多价才使用该客户 `customer_price_selection.invoicePreference`：`rx`、`solar` 或同币种同单位的 `highest`。选定配置仍多价、币种单位不同、缺单价或规则未指定时不猜价；未核对金额继续向普通成员隐藏，不回退旧已核对发票。明显的 Invoice No. / Invoice Number / 发票号表头不能显示成真实单据号。价格规则不会改写原档案，也不代表报价已发送。

管理员在页面先选客户再保存规则；普通成员只读取其授权客户规则。API `customer-price-selection-save` 要求 `customerAccountId`、`invoicePreference`（null 为取消偏好）、`expectedVersion` 和 `expectedSelectionSha256`；GET 的 `selections` 返回当前版本和摘要，没有记录时为 0 / null。旧版本或摘要冲突返回 409。通用 data 不返回规则，普通成员也不能经审计读到规则记录。

受控本地工具默认只预览，不载入可写运行时：

```powershell
node standalone/set-customer-price-selection.mjs --build-dir test-output/quote-review-build --config <私有已审核客户规则JSON> --dry-run
node standalone/set-customer-price-selection.mjs --build-dir test-output/quote-review-build --config <同份客户规则JSON> --apply
```

私有 JSON 包含上述四个 API 字段，以及 `expectedCustomer {id,customer,customerCode}`。客户姓名 / 编码 / 稳定 ID 必须与现有有效客户完全匹配；CLI 只使用已绑定的唯一创建者管理员身份，不读取密码或会话。新规则时版本 0、摘要 null；更新用当前完整记录的 canonical SHA256。apply 验证除了该客户选择记录和对应审计外，旧订单、客户、报价、档案、账号及原件记录字节不变。客户实际选择留在私有 JSON 和数据库，不硬编码到公开源码。构建验证与正式部署仍由管理员分别执行。

```powershell
node tests/run.mjs
node node_modules/typescript/bin/tsc --noEmit
node standalone/test-customer-price-archive.mjs
$env:DOON_BUILD_DIR='test-output/quote-review-build'
node standalone/build.mjs
node standalone/test.mjs
node standalone/test-customer-quotes-browser.mjs
```

测试仅使用合成账号、临时数据库、测试端口和合成原件。浏览器模块需要已安装 Playwright；可用 `DOON_PLAYWRIGHT_MODULE` 指向预装模块，不必修改项目依赖。构建、提交、推送和正式部署是不同步骤，不自动停止或重启生产服务。
