# 度昂订单协作中台 · 公司内网版

支持从订单原表的动态表导入明细，保留原列、源行号、跟单员和同键多行，按文件摘要和行号沿用稳定明细编号。原始 Excel 不修改。公开仓库不包含生产数据。

## 进入网站

- 本机：http://127.0.0.1:8787
- 当前公司内网：http://192.168.1.176:8787
- 管理员账号：`admin`。首次密码见主机 `lan-data/管理员首次登录.txt`，登录后必须设置个人密码。
- 网站使用公司自己的账号密码，与 ChatGPT 无关。
- 主机必须开机且连着公司网络；文员电脑需连接同一网络。不能通过访客 Wi-Fi 隔离网络访问。

首次开通需由 Windows 管理员运行 `开通内网访问.ps1`，只允许 192.168.1.0/24 网段访问本机 8787 端口。此操作不关闭防火墙。主机当前的网络名称为 Doon 2。

## 添加文员

1. 管理员登录后进入“成员与权限”。
2. 在“创建员工账号”填写英文登录账号、姓名、至少 12 位初始密码、角色、部门和订单查看范围。文员、客服 / 销售默认可查看共享总表；销售的“负责客户”用于分配可修改的客户订单。
3. 单独将账号和初始密码告知本人。员工首次登录必须改成自己的密码。
4. 在“把原表跟单员绑定到登录账号”中，将 CANDY / TINA 等原表姓名绑定到对应实际人员账号，“我的订单”就会按负责人显示。选择姓名及账号后，可查看原表明细总数、已绑定数和待绑定数；显示绿色“已全部绑定”时无需重复操作。员工需使用自己的账号进入“我的订单”，管理员的“我的订单”不会代替员工显示。
5. 需要更改部门、客户范围或停用账号，使用“编辑权限”；忘记密码时由管理员使用“重置密码”。

新增角色：生产管理人员可查询全部订单、维护生产进度和全部部门工序、办理供应商收货；源订单、结单归档、账号管理仍由原有 PMC / 管理员权限负责。财务人员可查询全部订单、在制和归档、收货记录及凭证并导出报表，不能更改业务数据。程序员可查看“系统维护”中的网站、数据库和备份状态，业务订单按另行分配的客户范围只读查询与导出，不可修改业务或管理账号。创建账号和编辑权限均可选择以上三个角色。

每位文员看到的是同一共享总表。查看范围和修改权限独立设置：PMC / 管理员可维护全表；文员只能维护本人跟进字段和所分配部门工序；销售即使可查看总表，也只能维护负责客户或本人订单的跟进及对客交期。管理员可在“编辑权限 → 订单查看范围”选择仅负责客户或本人订单。程序员和只读成员默认仍按分配范围查看。内部 `账号@doon.local` 是订单负责人关联标识，不是邮箱服务，也不需要员工注册邮箱。

## Excel 上传与页面提醒

- 上传完整《度昂订单管理表》：进入“上传与更新”，在“度昂原版工作簿导入”选择 XLSX，核对预览，再点击“确认导入此工作簿”。第 3 行表头自动识别，最多 4000 行，系统自动按每批 35 行写入。
- 完整原表误选在下方普通工作表入口时，会自动切换到原表预览。再次选择同一原表可以正常识别，已完成批次不会重复建单。
- 文员修改已有订单：先导出“可回传工作表”，保留明细编号和版本，再从下方入口上传。普通工作表每批最多 200 行、文件不超过 10 MB，表头自动识别后仍可调整；只能合并获分配的字段。
- 源订单整表导入由 PMC / 管理员执行。销售、财务等没有导入权限的角色，会看到彩色权限说明，不会出现无解释的空白页。
- Alice 等销售在“供应商收货”可查询可见订单的记录，会显示“交期维护权限 · 仅可查看”。登记、拍照收货和消数仍由获授权人员办理。
- 内网 HTTP 下供应商页已使用兼容的随机标识生成方式。页面遇到加载异常时，会显示可重试的提示卡片。

## 每天怎么使用

供应商页现为采购协作工作台，分为“交期与催交”“从总表选单”“供应商资料”“送货单与收货”。没有实际外发记录时，会显示总表订单和登记指引；不会用总表工序数量推测供应商或虚构外发单。

Candy、Tina 的 PMC 账号兼任采购，均可新增 / 修改供应商、登记外发、修改要求交期与外发数量、记录供应商回复日期和承诺交期、预计到货、本次复期数量、延期原因、下次催交日及跟进说明。其他角色可按订单查看范围查询，生产和仓库原有工序收货权限保留，外发建单和复期维护集中由 PMC / 管理员办理。

使用顺序：

1. “供应商收货 → 从总表选单”，搜索订单，点击对应明细的“登记外发”。
2. 填实际供应商、外发单号、工序、数量、外发日期、要求到货日及采购跟进人，保存后可接着填写复期。
3. “交期与催交 → 复期 / 催交”填写本次回复；晚于要求交期时填写延期原因。Candy 与 Tina 可接续操作，原始要求交期和每次变更均保留；同一版本同时提交时会阻止覆盖。
4. “今日待催交”等色块可直接筛选；“导出交期表”导出相同筛选的 Excel。提示为网站内提醒，不会自动向供应商发消息。
5. 回货后进入“送货单与收货”，拍照上传送货单，选择外发明细并确认实收。合格数减少外发欠数并更新对应工序，不良数量不消数。已收货记录不能被采购取消，外发数量不得改为小于合格实收数量。

未发生收货的外发可填写原因取消，历史保留。已有凭证的供应商、单号、外发日期不允许覆盖。供应商资料可停用；已有外发继续按实际收货办理，新开外发需选用合作中的供应商。

双击 `启动订单中台.cmd` 启动，程序在后台运行，不占用操作窗口。重复启动会先检查是否已经运行。主机上的 `lan-data/server-status.json` 会显示实际地址；`server.log` 与 `server-error.log` 保存运行信息。管理员可按需要使用 `停止订单中台.ps1`。

2026-09-16 增加后台守护：运行 `standalone/安装后台守护.ps1` 注册 Windows 任务 `DOON-Order-Workspace`，使用当前 Windows 用户的普通权限，不保存密码。用户登录 Windows 后自动启动；网站进程退出后约 5 秒重启，守护进程退出后由 Windows 每分钟检查恢复。已有健康服务会被监测，不重复启动。`lan-data/service-events.jsonl` 保存启动、退出码和恢复记录，`service-status.json` 显示守护状态。停止网站请使用 `停止订单中台.ps1`，它会同时暂停守护，避免维护期间自动启动；再次运行启动脚本恢复。公司主机关机、睡眠、断网或当前 Windows 用户注销期间仍不能访问，此配置不会改变电源设置或扩大防火墙范围。

如主机 IP 改变，旧的内网地址和专用防火墙规则需同步更新。建议由公司 IT 在路由器里为本机保留固定地址。现在的服务仅支持本机和私有 IPv4 网络；没有开通公网访问。

## 数据和备份

- 共享数据库：`lan-data/workspace.sqlite`，使用 SQLite WAL 事务协调多人写入。
- 原始工作簿、送货单与附件：`lan-data/files`。
- 完整备份：`lan-data/backups/日期时间/`。服务器启动后以及每连续运行 24 小时执行一次；管理员也可在成员页点击“立即备份”。备份后检查数据库完整性。
- 备份必须同时保留数据库和 files 文件夹。当前备份与主机位于同一磁盘，建议公司另存一份到独立磁盘；不要把数据目录复制到网页静态目录。
- 恢复时先停止网站，将备份中的 `workspace.sqlite` 与 `files` 复制到一个新的空数据目录，以 `DOON_DATA_DIR` 指向该目录后启动，核对记录再切换。保留原目录便于回退，不在运行中覆盖数据库或 WAL 文件。
- 初始密码文件由本机保存，仅供管理员首次使用，设置密码后可以删除。

## 技术交接

项目保留共享前端与业务 API；`standalone` 是独立登录、HTTP 服务、本地 SQLite / 文件存储适配及构建入口，`lan-dist` 是运行版本。不存在对外部身份头的信任，也没有公开注册入口。账号密码以带随机盐的 scrypt 摘要保存；会话放在 HttpOnly、SameSite=Strict cookie 中，闲置 2 小时或最长 12 小时到期，修改 / 重置密码会使旧会话失效。HTTP 版仅用于可信公司局域网；需要公网或不可信网络访问时应配置 HTTPS（已保留证书环境变量入口）。

实现参考：[Node.js SQLite 官方文档](https://nodejs.org/api/sqlite.html)、[OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP 会话管理建议](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

# 部门损耗与月报（2026-09-15）

1. 在部门录入工作台打开订单，录入本部门报工，在“部门损耗确认”选择工序。
2. 先核对 MES。MES 报工页有加工不良、来料不良和隔离不良字段，这些数可能包含待返工，不能直接作为报废。当前尚未自动连接 MES。
3. 若有 MES 已确认报废损耗，选择“MES 已确认报废损耗”，填写该订单明细、该工序的累计确认损耗和报工 / 报废处理凭证。单次报工数须先核对累计口径，不可直接替代累计数。
4. 若暂无 MES 已确认损耗，选择“部门核对公式”，核对累计投入（含补投）、合格完成数及仍在制数，系统计算累计损耗。投入 210、合格 204、仍在制 4，只确认损耗 2。待返工、待核实不良先计入仍在制。
5. 填实际确认日期、原因，勾选数量已核对，点击确认。上方有尚未保存的部门字段时，可以一次“保存报工并确认损耗”；服务端统一验证后原子保存。
6. 月报按确认日期归月，只累计本次损耗增减。例如 8 月累计损耗 2，9 月变为 6，则 9 月只增加 4。错误数量用“冲减更正”在当前日期登记，保留原记录。
7. 打开“部门损耗月报”或报表中心对应入口，选月份、部门、客户，导出 Excel。文件含部门月度汇总和全部确认明细，包括订单数量快照、投入 / 合格 / 在制、累计损耗、本次增减、来源、凭证、登记人及时间。

订单跨部门流转，部门涉及订单数和订单数量不可跨部门相加；各工序损耗合计不等同于成品短缺。未登记不代表零损耗。损耗不扣减订单数量，不改变包装入仓，不自动回写 MES。外发收货“不良数”仍须确认报废或返工后处理，不能重复记为来料与本工序损耗。

本部门文员仅能维护获分配部门；PMC、管理员、生产管理人员可核对全部生产部门；财务、客服及其他只读角色按既有订单范围查询和导出。已完成归档订单保留历史损耗与原月份报表，不能追加损耗；确需修正先由 PMC 按原流程恢复在制。
